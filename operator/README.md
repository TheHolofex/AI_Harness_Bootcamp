# Operator ritual — Move 1

**Deep operator mastery of AI direction and cothinking** is practiced here when the live module page calls for these files.

The Brief and Log are **not** blank homework. They are **produced interactively** with the AI in the module-specific direction and closeout chats named on the live page. Some modules reuse one direction/closeout chat; others split those jobs. That *is* cothinking: the machine helps you think clearly about direction and evidence; you keep mission ownership and verdict. Saved files, not chat history, carry continuity between tasks and modules.

The live HTML module page owns the learner sequence, tells you which of these references applies, and supplies the exact chat name. B1 is a guided build in `B1 — First Light Dashboard`; it does not use the generic direction/closeout pattern below.

## Where it lives for students

1. These standing files inside the **Codex app project**.
2. When a module uses the direction ritual, the exact module-first chat named on its live page. **`[MODULE] — Direction & Closeout`** is one pattern, not a universal name; copy separate direction, closeout, task, retry, reviewer, date, and model-role names exactly where shown.
3. Student pastes the prompt supplied by the live module page; the file starters are reference patterns.
4. Mission/build work happens in the separately named module chat. Never collapse judgment into the build chat.

## Ritual (when the module page invokes it)

```text
Exact module direction chat: co-write Brief → status LIVE
    → Exact module task/build chat: run the mission against the Brief
    → Exact module closeout chat: write the Log entry from saved evidence
```

The direction and closeout names may be the same when the live page deliberately reuses that role. A retry, independent review, isolated test case, different project boundary, or different model gets its own named chat. Reopening a saved chat is optional unless the page explicitly says to continue that same role.

## What the AI is allowed to do here

- Interview in short turns
- Propose tighter wording
- Challenge vague outcomes, uncheckable “done,” missing bounds, vibe evidence
- Write accepted text into the standing files

## What the AI is not allowed to do here

- Declare the brief LIVE without operator acceptance
- Assign ACCEPT/REJECT for the operator
- Run the mission inside the module's direction/closeout chat
- Accept “looks good” or model self-praise as evidence

## Facilitation notes

- P1–P7 module closeouts write their dated transfer seeds. P7 drafts and P8 finalizes the plan in `P7–P8 — 30/60/90 Plan`.
- Measurement spine after every adversarial (Move 4).

## Identity lock

The live module pages own the lesson sequence and current course facts. If Brief and Log become solo forms or instructor worksheets, the design has regressed.

## Chats

1. Exact module direction and closeout names from the live page — brief · log · pass bars; they may be one reused role or two separate chats
2. `[MODULE] — Adversarial Review — [DATE]` — new when the module page directs a frozen-prompt verdict/MVP attack
3. Measurement — `MEASUREMENT_SPINE.md` row after adversarial
4. `P7–P8 — 30/60/90 Plan` — the only intentionally shared chat; P7 drafts and P8 continues it only when the planning role and model match
5. Build/mission — execution only

**Course-wide rule:** one module, one task role, one model boundary per chat. Start retries, independent reviews, isolated test cases, and model changes in fresh named chats. The saved artifact is the handoff; a transcript is never required evidence. The sole intentional cross-module exception is `P7–P8 — 30/60/90 Plan`, because P7 and P8 continue the same saved plan in the same planning role; if the course model changes, P8 starts a fresh continuation chat instead.

In-course “peer who challenges verdicts” = adversarial AI chat.  
Named human challenger = transfer seed for the job.
