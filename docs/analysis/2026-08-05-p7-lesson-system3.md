# System 3 Analysis: P7 lesson architecture

Date: 2026-08-05

## Context

- P7 currently takes 3–3.5 hours to process eight rows. Most of that time goes to path restrictions, answer-key removal, held-before-write ordering, exception adjudication, permission checks, and closeout administration.
- The default flow sends only one of eight rows directly to the master output. The learner remains responsible for reading, deciding, copying, and promoting the rest.
- The stated first objective is volume, but the exercise shows little throughput and creates no product beyond two CSV files.
- P6 now owns the adaptive-agent experience: one goal, checker-driven revision, connected artifacts, a second wave, and one consequential human decision.
- P8 owns endpoint policy, refusal, and governed transfer. P5 owns hostile-input containment. P7 does not need another required safety lab.
- n8n remains useful because its graph makes mapping, routing, parallel branches, and fan-in visible to learners who do not write software.
- P7 also owns the first draft of the 30/60/90 plan. That transfer role should remain after the exercise changes.

Unknowns remain: cohort API-rate limits, current n8n node labels on the pinned install, time for 60 model calls, and how many learners arrive with a real workload they can describe without exposing work data.

## Problem Frame

Three useful statements of the problem:

1. **Curriculum:** P7 needs a capability that differs from P6’s adaptive loop and still completes Thursday’s machine-choice contrast.
2. **Experience:** the learner should watch one designed AI move propagate across enough work that the result feels larger than the setup.
3. **Delivery:** the exercise should survive current n8n UI drift, funded-key limits, and a mixed technical audience without returning to hours of prescribed clicking.

Assumptions under test:

1. P7 should preserve the fixed-workflow contrast with P6.
2. The emotional target can be the power of automation at scale, not only autonomous goal pursuit.
3. n8n is the right medium if learners operate and change a prepared graph instead of constructing every node from scratch.
4. A visible operating bundle creates more value than a classifier output.
5. Sixty initial records and a twenty-record second wave are large enough to reveal leverage without feeling artificial.
6. Structured output is the key interface between an AI station and the rest of a workflow.
7. Routing, parallel branch policy, and fan-in are the most transferable workflow mechanisms for this audience.
8. One branch-policy change applied across the batch teaches more than three manual exception decisions.
9. A deterministic row-count and artifact checker can remain backstage without turning assurance into the lesson.
10. Real-work transfer needs three choices—fixed, adaptive, or hybrid—because useful systems often place agentic work inside a designed outer graph.
11. The 30/60/90 draft can remain after the power run if it does not interrupt the reveal.
12. Current P7 visuals and optional gate-economics resources should leave the required path even if they remain available as advanced operations material.

## Perspectives

### Curriculum skeptic

Turning P7 into another autonomous mission would produce a second P6. The fixed-line slot is useful, but its mastery claim must move from governance to production leverage. This challenges the assumption that “feel the power” requires an agent choosing every next action.

### Learner advocate

The first useful result needs to appear within twenty minutes. Importing a prepared graph, attaching one model credential, and processing a substantial batch gives the learner an early reveal; prescribed construction can come later in small, meaningful edits. This challenges the assumption that building every node creates ownership.

### Workflow operator

Real automation power comes from turning unstructured intake into downstream work: structured records, routed queues, branch-specific policy, a recombined register, and a brief. A classifier followed by manual CSV promotion is unfinished automation. This challenges the assumption that an AI label is a sufficient product.

### Workshop engineer

Sixty sequential model calls may be too slow or hit provider limits. The prepared workflow should support small batches, keep exact model and credential setup to one node, and include an offline fixture-based verifier. This challenges the assumption that more rows automatically create a better room experience.

### Automation skeptic

A polished workflow can hide brittle routing behind a dramatic canvas. The learner must change one rule, rerun the same inputs, and explain the downstream difference. This challenges the assumption that pressing Execute once proves transferable understanding.

### Futurist

Node names and model connectors will move. Map, structure, route, fan out, fan in, rerun, and compare survive product churn. This challenges the assumption that UI construction detail is durable curriculum.

### Conflicts and agreements

All perspectives reject the eight-row gate lab as the core P7 experience. The main conflict is fixed workflow versus a second autonomous-agent mission. Keeping P6 as the adaptive peak and making P7 the automation-at-scale peak preserves a clean capability delta. The delivery concern sets a design constraint: the full batch may contain 60 records, while the workflow groups work into a smaller number of model calls or provides a cohort-sized fallback.

## Creative Reframes

1. **Factory line:** one skilled move becomes a station. Sixty items pass through it, route to four specialist branches, and return as one operating bundle. The learner experiences leverage as multiplication.
2. **Air-traffic flow:** the fixed graph does not make every judgment. It determines where each kind of work goes, which policy applies there, and how all branches return to one shared picture. This exposes the powerful middle between a rigid script and a free agent.
3. **Inversion—operate before construction:** import and run the production line first. Inspect the graph after the useful bundle exists. Change one branch rule, then reveal a second wave and rerun without rebuilding.
4. **Hybrid extension:** route a genuinely nonstandard subset to an adaptive subflow after the fixed-line lesson lands. This keeps hybrid composition visible without making another agent setup the required exercise.
5. **Pre-mortem:** the redesign fails if the batch takes most of the block, if the outputs are only labels, if learners cannot tell what one rule changed, or if the second wave requires a new workflow. Batch grouping, an operating bundle, before/after counts, and the same saved graph address those failures.

Active biases: sunk-cost attachment to the existing gate exercise, availability bias toward the newly designed P6 adaptive mission, and builder bias toward node construction as proof of learning. Mitigations: preserve n8n only where it serves a distinct mechanism, keep P6 and P7 emotionally powerful in different ways, and require a rule change plus second-wave rerun as the ownership evidence.

## Synthesis and Recommendation

Retain **P7**, retain **n8n**, and replace the current exercise with **The Production Line**.

The durable capability is:

> Turn one useful AI judgment into a designed production line that structures, routes, and recombines a real batch, then change the line once and see the decision propagate everywhere.

The learner arc:

1. Inspect 60 realistic intake records and the useful operating bundle that does not exist yet.
2. Import a prepared n8n graph and attach the already-funded xAI model in one place.
3. Run the batch: structure every record, route it to four specialist branches, apply branch policy, and fan the results into a master register, four team queues, a workload snapshot, and a run receipt.
4. Read the outputs before studying the nodes. Name the hours and handoffs the line compressed.
5. Walk the graph from map to structure to route to branch to fan-in.
6. Change one branch rule once and rerun. Compare how many records and downstream fields changed without row-by-row edits.
7. Reveal 20 new records and rerun the same saved graph. The bundle updates to 80 records without a new prompt or rebuild.
8. Re-slice one earlier course workload and one workload from the learner’s desk as fixed, adaptive, or hybrid.
9. Save the machine-choice seed and draft the 30/60/90 horizons after the production run is complete.

Remove from required P7 work: human-gate placement, poisoned rows, answer-key isolation, held-before-write construction, manual exception adjudication, manual CSV promotion, per-chat permission checks, a separate attack pass, and gate-economics study.

Keep backstage: synthetic inputs, project-local outputs, one credential attachment, batch-size fallback, deterministic artifact and row-count checks, saved execution evidence, and a clean rerun path.

## Blind Spots and Uncertainties

- A funded Windows pilot must establish whether 60 rows should run as individual calls or grouped batches.
- The prepared workflow JSON must be tested against the exact n8n version installed by pre-work.
- Model output consistency may require a structured-output parser or a small normalization node.
- A one-page workload snapshot may be easier to generate deterministically after fan-in than through another model call.
- Learners with no shareable real-work example need supplied workload cards for the transfer sort.
- The advanced human-gate resources need a new home or explicit optional label so strong material is not lost when it leaves P7’s required path.
