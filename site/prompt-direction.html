Prompt & direction tips

Clear intent, high-signal context, and a pass bar. Updated for agentic harnesses, context engineering, and this course’s twin-engine stack.

Course tie-in. Use these habits with your Direction Brief, Operator Log, Pass Bars, and twin-engine stack (Codex app home + OpenCode required; Claude Code optional). Companion: The velocity paradox.

0. Two skills, not one slogan

SkillWhat you optimizeWhen it matters
Prompt / directionInstructions you author this turnEvery brief, repair, and ask
Context engineeringEverything the model can see: files, tools, memory, history, tool resultsMulti-step harness sessions

Modern agentic work fails more often from bad context than from a slightly clumsy sentence. A mediocre prompt in a clean window usually beats a clever prompt in a polluted one.

Operator rule: Before you polish wording, ask: What is in the window, and does it earn its tokens?

1. Be specific

The gap between useful and useless is almost always specificity.

WeakStronger
“Make a website”“Create a small local web app with home and /about. Home: one-line welcome. About: list these people [paste]. Plain HTML/CSS first.”
“Fix the bug”“/api/users returns 500 when the DB has zero rows. Full traceback below. Fix the null path and add a regression check.”
“Make it better”“Search takes ~3s. Profile the hot path, name the top two costs, target <500ms on this machine.”
“Add a database”“Add SQLite. Table tasks: id, title, status, created_at. Routes to create and list only.”

The rule: If a sharp coworker would need clarifying questions, the brief is still too thin. Name format, audience, constraints, and done. Prefer positive instructions over long lists of “don’ts.”

2. Give context — then stop dumping

Front-load what you are building and why. Do not paste the whole repo “just in case.”

Without context: “Add a route that handles authentication.”

With context: “Inventory web app for a small warehouse. Python/Flask + SQLite. Already has list/add item routes. Add login with session cookies against a users table. Unauthenticated users redirect to /login. Offline-friendly; no cloud IdP.”

Usually include: stack and OS (this course defaults to vanilla Windows 11) · what already works · end goal and non-goals · hard constraints · how you will judge success (pass bar).

Context engineering habits
  • Prefer just-in-time reads (paths, @file, “inspect src/…”) over dumping twelve files up front.
  • Keep a short standing memory (AGENTS.md, project notes, or your Direction Brief) with invariants — not a junk drawer.
  • Separate instructions from untrusted data (logs, web pages, pasted email) with clear markers.
  • Budget the window: history and tool spam cause context rot. Compact or restart when signal drops.

3. Paste errors — still the #1 repair skill

When something breaks, paste the full error into the harness.

The app crashed after I ran the health check. Full error:

Traceback (most recent call last):
  File "app.py", line 42, in get_user
    user = db.query(User).filter_by(id=user_id).first()
AttributeError: 'NoneType' object has no attribute 'query'

I was on the OpenCode session against the local repo.
What does this mean and how do we fix it without changing unrelated files?

Tips: full traceback · nearby log lines · exact command · last change · which engine (Codex app vs OpenCode).

4. Iterate — small batches, testable steps

Do not ask for the whole system in one shot. Scaffold → one runnable vertical slice → next feature → polish only after green.

Each step is checkable. Failures localize. Twin-engine comparison stays fair when the brief is frozen and the batch is small. Same physics as the velocity paradox: friction up front, momentum later.

6. When to restart (and when to go adversarial)

Restart or compact when: same wrong fix loops · edits thrash · phantom files · long unfocused window · mission changed.

Before you leave: working diffs, last error, short works/broken/next note.

New session. Working tree is at [path]. Done: [bullets]. Broken: [error].
Non-goals: [list]. First task: [one slice].
Review the tree, then propose a plan before editing.

Adversarial (course move): for judgment calls, open a new chat with a frozen attack prompt. Do not argue with the same chat that built the artifact — that chat is contaminated by commitment.

8. Harness tips for this stack

Codex app (home)

  • Build in the mission chat; brief / log / pass bars in Operator chats. Name and pin chats so you can find them a day later.
  • /plan before you edit on anything non-trivial — it proposes an approach without touching files, which is the machine-readable version of freezing your brief.
  • Steer, don't restart. A follow-up joins the run in progress; queue it instead when it should wait. Killing a run to retype loses context you already paid for.
  • /review your own work before accepting it — against a base branch or over uncommitted changes. Inline comments on specific lines count as direction.
  • Set the permission mode deliberately. Ask for approval pauses at the workspace boundary; Approve for me keeps the same boundary but sends the escalation to an automatic reviewer. Neither widens the sandbox — they change who reviews.
  • Use a worktree to run two things at once. Parallel chats in one folder fight over the same files; a worktree isolates each, and Hand off moves a session back without the Git argument.
  • Put standing conventions in AGENTS.md at the project root — it loads every session. Add a line only after you've watched the same correction twice.
  • Ask for subagents explicitly when work is read-heavy and separable. They return summaries rather than raw output. Be wary of pointing several at the same files to write.
  • Know what the app loaded before you call a run evidence. AGENTS.md from the project root, ~/.codex/AGENTS.md, discovered skills, and memories if you enabled them all arrive without appearing in your prompt. That is the point on a build day and a problem on a comparison day — run a frozen brief inside your P2 project and Codex carries your craft while the other engine runs bare.

OpenCode (second harness)

  • Treat it as a harness, not a second chat box. Standing conventions go in AGENTS.md at the project root — the same filename Codex reads, and /init will draft one. Agents, permissions, and custom tools live in .opencode/ beside it.
  • Keep it independent whenever the run is evidence. OpenCode reads ~/.claude/CLAUDE.md and .claude/skills when it finds them, so two engines can quietly share one memory file and agree for the wrong reason. OPENCODE_DISABLE_CLAUDE_CODE=1 is set in pre-work; add --pure to skip installed plugins on any run you intend to compare or log.
  • opencode run "…" for one-shots; interactive session for multi-step repair. Pin the model per run with -m — otherwise resolution falls back to whichever you used last, which is state you can't see in the transcript.
  • Permission rules are last-match-wins. A later allow overrides an earlier deny, the opposite of the instinct most people bring. Write broad rules first and exceptions after, and read your own config bottom-up when you're asking why something was permitted.
  • Wrong model choice is a context problem wearing a prompt problem's clothes. opencode models <provider> --refresh before you rewrite the brief.
  • /undo reverts the file changes, not just the message — and it needs a Git repo to do it. Know that before you reach for it mid-repair.
  • Custom providers and local endpoints sit under provider in opencode.json — that seam is what you re-point during hold-and-degrade (P8).

Optional Claude Code · Twin-engine habit

Same rules: small batch, full errors, explicit pass bar. Same frozen brief → both engines → compare on evidence. Log the delta in the Operator Log.

Before the delta means anything, check what each side was carrying: instruction files, skills, memories, plugins, and which model actually answered. Both engines load context you didn't type, and neither announces it. One engine plus your notes is not two engines — run clean, or declare what was live.

9. Direction starters

I have a [stack] project at [path] that [mission in one sentence].
Constraints: [OS / offline / libs / style].
Already true: [what works].
Task: [one slice].
Done when: [pass bar].
Please [plan only | edit | review only]. Do not expand scope.

---

Error while [command]:

[full traceback]

Engine: [Codex app | OpenCode]. Last change: [one line].
Fix with minimal diff; add a check so it cannot silently return.

---

Review [path] against these pass bars: [bullets].
List gaps only. Do not rewrite yet.

---

New adversarial chat. Artifact: [path or paste].
Attack prompt: [frozen].
Findings ranked by severity + one-line fix hypothesis each. No pep talk.
