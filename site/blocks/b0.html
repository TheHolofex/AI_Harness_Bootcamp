Why this block exists

A harness is the setup around a model that lets it act: tools, files, permissions, instructions, and your accept/reject loop. Today you will feel that loop before we name every part of it.

Pre-work already walked install with a verify at the end of each step. Monday still opens with an install clinic — about two hours expected, no hard wall-clock boundary — so remaining blockers die under staff eyes. Then we direct. The clinic is finish-and-prove, not a substitute for skipping pre-work.

Clinic stretch done (~2 hr expected, no hard wall): setup log present, four-agent smoke files in Explorer (re-run verifies if needed), OpenCode version and Codex app sandbox mode recorded — those are what differ between machines when something behaves oddly later in the week. A key that has hit its spending cap looks like an authentication failure, not a bill: a 429 or a quota message on a tool that worked yesterday is a staff fix, not a reinstall. Still blocked → rescue track in parallel.
  3. Open mission_flesh/b0/reports/ (synthetic mission reports). Confirm multiple report files. Note fields you’ll map (time, tag, summary). Your outcome: a small local web map or timeline+filter view over those reports.
  4. In a build chat (not the operator chat), direct Codex to build a local single-page viewer (HTML/JS OK) with timeline and filters over the reports. Have it inventory the folder and propose a minimal data shape first, and load from the folder or a generated data.json. Offline preferred — see the sample build prompt below.
  5. Open the page (local server if needed). You can see multiple reports at once. This and the four checks after it are accept checks you run yourself.
  6. Timeline sorts or filters events by time in an observable way.
  7. Change a filter; the list/map updates correctly.
  8. Prove a must-not case (wrong filter empty state, or excluded report stays out) — a view that must not show a wrong report. Verify it yourself.
  9. Add reports/DELTA_new.md (provided); show refresh/rebuild reflects it — or document the break and your redirect.
  10. In operator chat: goal → act → observe → correct → accept, using this mission — not generic slogans.

Operator pulse — required every block

The same six-beat ritual closes every half-day: it is how a mission becomes evidence. Paste-ready prompts →

  1. Build work stays out of the operator chat — the trail is the point.
  2. Back in Direction & Log: what you directed, mid-run changes, verdict (ACCEPT / REJECT / ACCEPT WITH FIXES), evidence pointers, what you still own.
  3. Against B0’s MVP list: met / not yet with evidence pointers. No inflation.
  4. Chat Adversarial — B0: frozen prompt + artifacts + provisional verdict. Copy the final line into your log: ADVERSARIAL: stood | wounded | failed. Fix if wounded.
  5. Ritual 0–3 · mission HIT/PARTIAL/MISS · quality STRONG/ADEQUATE/WEAK · time to result (minutes). Deep mark if this block has one.
  6. Chat Operator — Transfer 30-60-90: paste the every-session prompt. A session-log row is required even if the seed is small today.
