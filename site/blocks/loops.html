Use the full 30 minutes

00–05 min See the loop

Follow one complete cycle: goal → act → observe → judge → adapt or finish. Another turn is useful only when the observation can change what happens next.

05–12 min Place control deliberately

Use a fixed workflow when you know the path in advance. Let the model choose the next step only when the work genuinely depends on what it discovers.

12–21 min Choose by evidence

Match routing, parallel work, orchestrator–workers, handoffs, or evaluator–optimizer to an observed need. A pattern must remove a bottleneck or improve the accepted result.

21–27 min Engineer the finish

Set acceptance checks, turn and cost limits, failure handling, and a human hand-back. A loop without a credible finish condition is an expense, not a capability.

27–30 min Carry one rule into P4

Build the least elaborate personal harness that completes the P4 goal, leaves evidence you can inspect, and can run again without reconstructing the method from chat history.

Choose a pattern from the shape of the work

Start with one capable agent and a clear finish line. Add a pattern only when the current run shows why you need it.

Evidence in the workSmallest fitting patternWhat must be true
The steps and their order are knownSequence or prompt chainEach step produces a checkable input for the next. Keep path selection in code or procedure.
Inputs fall into stable, distinct classesRoutingA wrong route is visible, and each route has a genuinely different prompt, tool set, or process.
Several tasks do not depend on one anotherParallel workThe tasks can run independently, and one named owner or rule merges the results without hiding disagreement.
The necessary subtasks emerge only after inspectionOrchestrator–workersThe split reduces context or time, worker scopes do not overlap wastefully, and the orchestrator can verify the return.
A specialist should own the next part of the interactionHandoffOwnership changes explicitly, and the next agent receives only the context and authority it needs.
A draft can improve against explicit criteriaEvaluator–optimizerThe evaluator can point to a correctable gap. Cap the revisions and stop on pass, budget, or hand-back.
The path cannot be known until tools return observationsAgent loopTool results can change the next action, available tools are bounded, and completion is checked outside the model’s confidence.
The operating test: Compare the accepted result, elapsed time, model and tool calls, and human review before and after a pattern is added. If it does not improve the goal enough to justify its cost and failure surface, remove it.

Turn the P4 knowledge system into your harness

P4 gives the loop a real job: turn bounded source material into director-ready knowledge with trails you can inspect. The finished product—not the number of agent features you used—is the measure of success.

Goal Define the accepted result first

Name the question, saved product, evidence standard, and decision the result must support before the loop starts.

Context Load what this job needs

Personalization means preserving your source boundaries, recurring rules, preferred output, and known constraints—not pouring every note into every run.

Control Add one justified pattern

Let the evidence choose. Parallelize independent retrieval, route distinct questions, or use an evaluator when a checkable draft can improve.

Observation Inspect the state the work changed

Open the saved files, walk the citations, read the carrying sentences, and treat tool errors or missing evidence as observations the next step must address.

Finish Stop on evidence, not momentum

Accept when the product passes. Hand back when evidence is missing or judgment remains yours. Stop when another turn cannot change either condition.

Reuse Keep the method outside chat

Land durable instructions, procedures, and acceptance rules in the harness you own so the next real goal starts from the working method.

Primary sources behind the pattern map

These references use different frameworks, but they agree on the useful distinction: some paths are defined in advance, while an agent loop chooses actions from observations at run time.

  • OpenAI Agents SDK · Agent orchestration — model-led and code-led orchestration, including managers, handoffs, evaluator loops, and parallel work.
  • Anthropic · Building effective agents — the simplest-system rule and practical routing, parallelization, orchestrator–workers, and evaluator–optimizer patterns.
  • Google Agent Development Kit · Template agent workflows — deterministic sequential, loop, and parallel control-flow structures, with current guidance toward graph and dynamic workflows.
  • LangGraph · Workflows and agents — implementations of chaining, routing, parallelization, orchestrator–worker, evaluator–optimizer, and tool-using agent loops.
  • Yao et al. · ReAct — the original reasoning-and-acting pattern in which external observations inform the next reasoning and action step.
