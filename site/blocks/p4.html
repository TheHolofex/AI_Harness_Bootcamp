Design the brain before you build

Five rules control this run. Use them when you review each result.

1. A second brain is a product with a door

A chat does not provide a durable, structured store. A vault with a controlled write path supports audit, cold retrieval, repair, and intentional later updates.

MCP is the sanctioned door. The boundary is larger than the door. It includes project topology, per-agent permissions, denied filesystem tools, ask-gated writes, human approval, and tool receipts.

2. Reuse the PG dispatch pattern

Keep worker dispatch short. Use the saved PG pattern and the four fixed partitions.

Put your effort into the note schema, hub structure, director merge, cold query, and audit.

3. Citations must support audit

Each note carries the full source record. Include source ID, raw path, file SHA-256, publisher, dates, locator, excerpt, claim, confidence, uncertainty, and tags.

The tags cover route leg, mode, factor, and threat class. A note without that package does not enter the brain.

4. Threat material ends in protection language

Open sources describe interference classes against rail, port, and sealift. Your notes answer what to protect, detect, and recover.

Do not rank targets. Do not teach access methods. Do not optimize attack effects.

5. Markdown cannot prove the write path

Anyone can drop a file into a folder. Capture MCP receipts and the permission snapshot.

The verifier checks the recorded receipt structure. The Windows validation must also compare receipts with exported OpenCode tool events.

The external integrity snapshot lets another operator check the finished vault's path hashes. That check proves integrity. It does not prove authorship.

$integrity = "$evidence\P4_INTEGRITY_$stamp.json"

# The course entrypoint verifies semantics before it writes outside the vault.
py -3 $verifier $vault --write-manifest --external $integrity
if ($LASTEXITCODE -ne 0) { throw "Brain verification or integrity snapshot failed." }
py -3 $verifier $vault --check-manifest $integrity
if ($LASTEXITCODE -ne 0) { throw "Live-vault integrity check failed." }

# Prove change detection on an exact disposable target, never on the live vault.
$probe = Join-Path $env:TEMP ("p4-integrity-probe-" + [guid]::NewGuid().ToString("N"))
New-Item -ItemType Directory -Path $probe | Out-Null
try {
  Get-ChildItem -LiteralPath $vault -Force |
    Where-Object { $_.Name -notin @(".obsidian", ".git", "__pycache__") } |
    Copy-Item -Destination $probe -Recurse -Force
  Add-Content -LiteralPath (Join-Path $probe "MOC.md") -Value "`nmutation probe"
  $probeOutput = @(py -3 $verifier $probe --check-manifest $integrity 2>&1)
  $probeExit = $LASTEXITCODE
  $probeOutput | ForEach-Object { Write-Host $_ }
  if ($probeExit -eq 0 -or (($probeOutput -join "`n") -notmatch "changed=MOC.md")) {
    throw "Mutation probe did not identify changed=MOC.md."
  }
  Write-Host "PASS disposable mutation detected"
}
finally {
  Remove-Item -LiteralPath $probe -Recurse -Force -ErrorAction SilentlyContinue
}

py -3 $verifier $vault --check-manifest $integrity
if ($LASTEXITCODE -ne 0) { throw "The untouched live vault no longer matches." }
Get-Item $integrity
Remove-Item Env:OBSIDIAN_REST_API_KEY -ErrorAction SilentlyContinue
