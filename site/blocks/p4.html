Design the brain before you build

Five rules control this run. Use them when you review each result.

1. A second brain is a product with a door

A chat does not provide a durable, structured store. A vault with one write role supports audit, baseline, and later intake.

MCP is the sanctioned door. The boundary is larger than the door. It includes project topology, per-agent permissions, denied filesystem tools, ask-gated writes, human approval, and tool receipts.

2. Reuse the PG dispatch pattern

Keep worker dispatch short. Use the saved PG pattern and the four fixed partitions.

Put your effort into the note schema, hub structure, director merge, cold query, and audit.

3. Citations must support audit

Each note carries the full source record. Include source ID, raw path, file SHA-256, publisher, dates, locator, excerpt, claim, confidence, uncertainty, and tags.

The tags cover route leg, mode, factor, and threat class. A note without that package does not enter the brain.

4. Threat material ends in protection language

Open sources describe interference classes against rail, port, and sealift. Your notes answer what to protect, detect, and recover.

Do not rank targets. Do not teach access methods. Do not optimize attack effects.

5. Markdown cannot prove the write path

Anyone can drop a file into a folder. Capture MCP receipts and the permission snapshot.

The verifier checks the recorded receipt structure. The Windows validation must also compare receipts with exported OpenCode tool events.

The external baseline lets another operator check the finished vault's path hashes. That check proves integrity. It does not prove authorship.

If you get stuck

  • MCP will not connect. Return to the three Stage 01 screenshots. Confirm Obsidian is open on %USERPROFILE%\Vaults\p4-vault, the plugin switch is on, Enable non-encrypted (HTTP) server is on, and the HTTP MCP row has a green check. Close other Obsidian vault windows. Then rerun the unchanged verification block; its authenticated MOC.md check identifies a wrong vault before OpenCode starts.
  • The vault looks locked or read-only. Stop every P4 OpenCode session and close Obsidian before you archive or reseed. Do not run PowerShell as administrator and do not use icacls, attrib, ownership changes, or a symlink. Run Start-P4.ps1 Setup again only after the old folder has been renamed; setup creates a normal writable folder and tests it.
  • The launcher reports an inherited-policy mismatch. Leave the vault unchanged. The launcher has stopped because another OpenCode setting would alter the course boundary. Close that PowerShell window, open a new one, set the two course API variables again, and rerun the launcher.
  • Brain verify HOLD on sources. Open the named note. Fill every source field. Make the excerpt long enough to identify the line.
  • Baseline check fails immediately after freeze. You edited a file after freeze. Run --write-manifest --external again.
  • Workers invent facts. Revoke web. Point them only at ASSESSED_SLICE ids. Reject bundles that miss sha256.
  • Windows or Obsidian is unavailable on this machine. Read BLOCKED.md in the course repo root for the instructor path. Still complete schema study and verifier dry-runs against reference_fixtures/complete_vault.
