Learn the ideas before you build

Five ideas carry the afternoon. Read them once. Come back when a step needs the reason.

1. Several agents cost you before they help you

Every agent you add costs coordination, context, and waiting before it returns anything. So before you spend that cost, save what one agent can do alone on the same job. That first answer is your comparison. Without it, a busy multi-agent run can look successful even when it found nothing new.

Save the first answer before you write the scores, and leave it unread until the end. If you read it first, you will know what it missed. Then you will write scores that reward finding exactly that. The point of scoring is to learn something you did not already decide.

At the end, the honest question is simple: what did several agents find that one agent did not? If the answer is "nothing much," that is a finding about this job. It is not a failure. It is worth more than a run that was only busy.

2. Count what you can count. Do not fake the rest.

People often want "recall": the share of all relevant material found. That needs a known list of everything relevant in the documents. Nobody has one. Building it would mean reading all 104 files. A score you cannot compute becomes a guess, and a guess tells you what you already believed.

You can count two other things. Coverage: the decision names points an answer must settle, and each is either addressed or openly left open. Source backing: each kept finding names a file and quotes the words that carry the claim. Both are countable without knowing the right answer in advance. Both would change if the decision changed. That is how you know the scores are doing real work.

3. Different paths means different reading, not different answers

The obvious test of whether agents searched differently is whether they came back with different things. That test is wrong. Two agents that reach the same important fact by different reading give you independent agreement. That is valuable. Treating it as waste teaches you to prize novelty over truth.

Judge the paths by what went in. Which files did each open? Which people or assets did each chase? Which time windows did each cover? What was each forbidden to read? If those inputs are the same, the paths were never different, no matter how different the answers look.

A limit written only in an agent's instructions is a limit it may ignore. A limit built into the tools it was handed is a limit it cannot ignore. That is the same lesson as this morning: advice is not the same as code that runs anyway.

4. Trying to break a finding is not a vote

After search, you do not ask checkers to improve findings. You ask them to knock findings down against the sources. They add nothing. Findings survive or they die.

The math is not democratic. One current, authoritative source that contradicts a finding kills it, even if four other files still repeat the old figure. This document set is built to punish counting. Four current planning products quote one bridge figure. One later signed document from the issuing authority withdraws it and gives another. Count the sources and you get the wrong answer with confidence. The later signed document governs.

Surviving a challenge also does not mean proved. It means nobody broke the finding with what they had. When a later step upgrades "survived" into "proved," the finding has been cleaned up. That usually happens when answers are combined.

5. A source check can prove a quote exists. It cannot prove the source backs you.

At the end, every claim must walk back to a file that still serves it, or the run fails. The check can prove three mechanical facts: the file exists, it is the one cited, and the quoted words are in it.

The check cannot prove the source means what your claim says. That is your judgment. The danger is not that the check fails to do that work. The danger is that a green check looks like it already did. Keep the two results apart in the output: quote found, and source backs the claim. A green report beside a claim the source does not back is true and misleading at the same time.

Stage 04 · Stop the search on a written rule

Skill · Knowing when several agents help, then work division You decide what counts as new, how many rounds must run before "nothing new" means anything, and the hard limit.

Search has to end. Two honest endings exist: nothing new came back, or you hit the hard limit. Both are fine. A run that cannot say which one happened is not fine. Write the stop rule before the next round starts.

Paste this into P3 — Run:

Run further search rounds under these rules, written to ledger\stopping.md
before the next round starts:

- Continue with the same four named custom agents on the same restricted
  surfaces. Do not widen a route or substitute a generic agent.
- A finding is NEW if no kept finding already cites the same file for the same
  obligation. Restating a kept finding in different words is not new.
- Minimum two rounds. One empty round straight after the first pass is a slow
  start, not saturation.
- Maximum three rounds, and at most fourteen kept findings in total.
- Stop when a round returns nothing new, or when the ceiling is reached.

At the end write ledger\terminal.md naming which rule fired: SATURATED, or
BUDGET_EXHAUSTED with the obligations still unresolved listed by number.

BUDGET_EXHAUSTED is a real ending and I would rather have it than a run that
pretends the ceiling was saturation. Do not pad findings to reach fourteen, and
do not drop good ones to stay under it.

What you should see. A stop record naming one rule, and at most fourteen findings. If it stopped on the hard limit, the unresolved required points are listed. That list is part of the answer, not a defect in it.

When it does not. A run that reports "no new findings" after two rounds while required points are still untouched has defined "new" too loosely. Tighten it to file-plus-required-point and rerun the last round.

A verifier may use the northwind_evidence tools and nothing else. Its only job
is to defeat the finding it was given. It adds no findings of its own and
proposes no rewording.

Disposition rules, and they are not a vote:
- One current, authoritative source that contradicts a finding DEFEATS it,
  regardless of how many challenges that finding has already survived.
- Where two sources conflict, the later one from the issuing authority
  governs, and an explicit withdrawal of an earlier figure settles it.
- Repetition is not authority. A figure appearing in four products and
  contradicted by one later signed document loses.
- A finding nobody could defeat is recorded as SURVIVED, never as PROVED.

None of these has one right answer. Each changes what you build. Have the argument before somebody has to live with your choice.

  • The multi-agent run found little the single agent missed. Was the afternoon wasted? No. You now know something about this job that you could only learn by measuring it. Next time you can spend one agent instead of six. The waste would be running several agents for a year without ever checking. The hard version: how many of your current multi-agent habits have never been compared against one agent doing the same work?
  • A finding survives two checkers. How much is that worth? Less than it feels. It means nobody defeated it with the sources they reached. That is a statement about the checkers as much as about the finding. The honest word is survived, not proved. Watch how strongly you want to upgrade it anyway.
  • Repetition really is evidence sometimes. When? When the repetitions are independent — different people observing separately and agreeing. It is worth nothing when they are copies. In a document set, most repetition is copying. The test is not how many say it. The test is how many found out separately.
  • The source check passes a claim built on an outdated source. Who is supposed to catch that? The weight rule, if you wrote it well, and you if you did not. This is the clearest case of a check working exactly as designed while the run is still wrong. A green light is not the same as a right answer.
  • Should the package carry a default answer for points it usually settles the same way? Tempting. It also turns a method into a template that confirms itself. Fix how the question is asked. Do not fix what comes back.
  • The hard limit stopped the search with required points still open. Do you ship? Ship the answer with the gaps named. That is what the decision-maker needs on the 22nd. Shipping a complete-looking answer with quietly unaddressed points is the only genuinely wrong move here.

The same run on other desks

  • Any recurring due-diligence question: a vendor, a site, a supplier. Several source types, conflicting ages of document, and a decision with a date on it.
  • Incident review: the same shape with logs, tickets, and chat as the documents — and the same trap, where the loudest repeated account outranks the one authoritative record.
  • Any question you are asked quarterly: the second time you answer it from scratch is the signal that the method should have been the deliverable.

Optional field guide · 45–60 min

Before agreement becomes independent agreement

Independence Is a Spectrum gives you a way to work out whether two sources that agree were ever exposed to different evidence. Use it when the combine step is about to raise confidence on two findings that may share one origin.

The one-agent answer is saved and settled. The scores are countable. Four paths differ by what they read. The search named its own stop rule. Findings died to authority rather than head count. The combine step ran twice under a rule written first. The source check failed on planted claims. The package names its inputs without carrying this question's answers. If you get stuck

  • /mcp shows no server. Check .codex\config.toml uses forward slashes and absolute paths, that npm ci completed in evidence_surface, and that you fully quit and reopened the app. Run node server.mjs --root "..\need\corpus" --validate-only first. If that fails, the config is not the problem.
  • An agent says a file is not on this tool set. That is the limit working. Either the path was not meant to reach it, or the tool set was cut too narrow. Decide which before you widen anything.
  • A table query returns nothing. Check the identifier column first. A reading from one station or sensor does not transfer to another. The wrong slice returns an empty set or, worse, a plausible one.
  • Everything about September comes back empty. It should. The exports stop at the decision date. Evidence about the window is past pattern and forecast. An agent that insists on September readings is asking for something nobody could have on the 22nd.
  • The checkers defeated nothing. Check they used the tools. A checker that rereads a finding and agrees has not attacked it. Give it the sources and the instruction to defeat, not to review.
  • The combine step reads like two reports stapled together. The conflict rule is missing or too vague. Name what happens to disagreement before combining again. Require conflicts to appear as conflicts.
  • OpenCode returns nothing. Capture its output rather than asking it to write files. Confirm $env:HB_XAI_MODEL is set, and run opencode models xai --refresh to check the key is reaching it.
  • You want a fifth agent. Write down what it would do that the four cannot. Then check whether that is a new path or just more of one. Usually it is the second.
