Why this block exists

Models are callable components. When they disagree, that disagreement is a sensor. Your job is adjudication with evidence outside either model’s confidence.

What you will leave with

  • Run BRIEF-v1 unchanged on the Codex app and OpenCode
  • Run identity declared for both engines — model, version, folder, context loaded
  • Comparator table; ≥3 material disagreements or proof of search
  • Kill at least one model-asserted claim
  • Supervisor-readable adjudication note
  • Transfer P3 seed; full pulse
  • Stretch: Many Minds — baseline, synthesis, and a delta sheet that defends whether parallel helped (optional)

Before you start

  • Confirm operator templates are present in your Codex app project (DIRECTION_BRIEF.md, OPERATOR_LOG.md)
  • Both apps signed in

Run of exercise

Work these in order and check each off as its proof exists. Progress saves in this browser — the same tick shows on the home page.

  1. Open chat Operator — Direction & Log. Paste the brief starter. Fill all five fields: Outcome, Done looks like, Bounds, Evidence standard, Stop/hand-back. Status must be LIVE before the mission — vague “explore the data” outcomes get challenged; name the artifact.
  2. Path: instruments/p3_frozen_brief/BRIEF-v1.md.
  3. Folder: instruments/p3_frozen_brief — the corpus including watchlist.csv. Joins use watchlist.csv IDs only — models do not invent join keys.
  4. Save raw output. Do not change the brief between engines.
  5. Same brief, same corpus. Run with --pure, model pinned with -m.
  6. Fill the run-identity table first — model id, version, folder, context loaded — then the side-by-side fields. Count material disagreements (or document low-separation search).
  7. Show the assert + why discarded using non-model evidence.
  8. Final operational picture someone cold could read.
  9. Single-engine ban, kill rule, comparator habit.

Settle what each engine is carrying before either one runs

Both load context you never typed and neither announces it: the Codex app picks up AGENTS.md, skills, and memories from wherever you launch it — including the harness you hot-rodded in P2 — and OpenCode reads ~/.claude/CLAUDE.md and .claude/skills unless OPENCODE_DISABLE_CLAUDE_CODE=1 is set. Run from a clean folder holding only the frozen corpus, or write down exactly what was live on each side. One engine plus your notes is not two engines. An advantage you didn't declare looks exactly like a capability you don't have — if the two sides ran with different context, that is a finding about your setup, not a disagreement between models.

Operator pulse — required every block

The same six-beat ritual closes every half-day: it is how a mission becomes evidence. Paste-ready prompts →

  1. Build work stays out of the operator chat — the trail is the point.
  2. Back in Direction & Log: what you directed, mid-run changes, verdict (ACCEPT / REJECT / ACCEPT WITH FIXES), evidence pointers, what you still own.
  3. Against P3’s MVP list: met / not yet with evidence pointers. No inflation.
  4. Chat Adversarial — P3: frozen prompt + artifacts + provisional verdict. Copy the final line into your log: ADVERSARIAL: stood | wounded | failed. Fix if wounded.
  5. Ritual 0–3 · mission HIT/PARTIAL/MISS · quality STRONG/ADEQUATE/WEAK · time to result (minutes). Deep mark if this block has one.
  6. Chat Operator — Transfer 30-60-90: paste the every-session prompt. A session-log row is required even if the seed is small today.
