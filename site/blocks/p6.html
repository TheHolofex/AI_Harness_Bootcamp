How Goose works this watch

One mission drives the work; the current state decides what Goose does next.

One launch gives Goose the full job

You do not issue a chain of prompts. The launcher keeps your full installed Goose profile and adds the built-in Developer toolkit for this mission. Goose reads the reports, decides how to organize the watch, builds the dashboard, checks the result, repairs what failed, and stops when the work holds.

goal → inspect → choose → act → check → revise → finish

The dashboard is frontstage; mission state is backstage

command_center.html is the operator product. It should make priorities, actions, evidence, and resource choices readable in one page. mission_state.json is the machine-readable memory behind it, which lets Goose revise the same watch instead of starting another summary.

Wave 1 permits a provisional choice

The first reports leave one mobile power unit between two urgent needs. Goose must make and explain a provisional allocation so the morning product is useful. The agent is allowed to move the work forward; its choice remains visible for you to judge.

Wave 2 returns intent to the operator

New evidence changes the situation: Route Bravo reopens to light vehicles only; Bridge Foxtrot needs ambulance clearance by 07:10 for a 07:20 arrival; Cold Store 7 reports its fixed generator online at 06:44; and bridge message EV-018 repeats EV-017 but must not create duplicate work. You state the operating intent. Goose decides how to carry it through the revised command center.

PASS is the stop signal

The final P6 VERIFY PASS line tells you the mission check cleared. Your work is to read the command center and decide whether its priorities and explanation are usable.

P7 uses a different machine

This afternoon, P7 sends every row through a fixed line that you design in advance. P6 is state-driven: Goose chooses the next action from the changing watch. P7 is path-driven: each row follows the same stations.

Run of exercise

Five stages take one command center through its first watch, one changed situation, and one operator closeout. Check each outcome only after you can see its named result.

Stage 01 · Launch native Goose

This step hands the whole overnight watch to Goose. The launcher checks the setup, prepares runs\current, and starts one autonomous xAI run.

Open PowerShell anywhere, then paste this complete command:

powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\Documents\HarnessBootcamp\AI_Harness_Bootcamp\mission_flesh\p6\scripts\Start-P6.ps1"

The launcher names any setup problem before the run starts. Let Goose continue without another prompt; the completed command center opens when it finishes.

What you should see. The console ends with a line beginning P6 VERIFY PASS wave=1, then your browser opens the local command center.

The mission has been handed over once when full Goose runs from the supported launcher and opens the Wave 1 command center.

Stage 02 · Read the Wave 1 command center

Read the page as the morning watch officer would. You should be able to find the most urgent situations, what happens next, which reports support the picture, and where Goose provisionally sent the mobile power unit.

If the browser did not open, paste this in the same PowerShell window:

Start-Process "$env:USERPROFILE\Documents\HarnessBootcamp\AI_Harness_Bootcamp\mission_flesh\p6\runs\current\command_center.html"

What you should see. One polished page carries the watch, including the provisional resource allocation and the reason behind it. The backstage file mission_state.json sits beside the page, but you do not need to read JSON to operate the watch.

Wave 1 is complete when command_center.html opens, the provisional allocation is visible, and the page is useful without consulting the raw report folder.

Stage 03 · State one operating intent

The situation has changed. Route Bravo is open to light vehicles only. Bridge Foxtrot needs ambulance clearance by 07:10 for a 07:20 arrival; its powered gate and inspection rig need MPU-1 to make that deadline, while manual clearance is estimated at 07:35. Cold Store 7 reports its fixed generator online at 06:44, freeing the unit from that site, but Relay Kestrel's energized bypass still needs MPU-1 too. State what you want protected or restored and the sequence that matters. Goose will choose the detailed edits.

Choose one direction. Stage 04 gives you a complete command for each choice.

  • Ambulance route first. Clear Bridge Foxtrot for the ambulance even if Relay Kestrel restoration slips.
  • Coordination window first. Protect Relay Kestrel's regional coordination window while Bridge Foxtrot continues with manual clearance.

Both are valid. Your choice sets the outcome; Goose still owns the detailed revision.

Your intent is ready when another operator can tell what you want protected, restored, or sequenced first. You own that direction; Goose owns the revision plan.

Stage 04 · Update the same command center

This launch adds the new reports and passes your intent to the same mission. Goose must retain what still holds, cancel work made obsolete by the correction, add new work, and explain the difference on the page it already built.

Paste one complete command in PowerShell—the one that matches your choice.

Ambulance route first

powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\Documents\HarnessBootcamp\AI_Harness_Bootcamp\mission_flesh\p6\scripts\Update-P6.ps1" -Intent "Clear the ambulance route first, even if relay restoration slips."

Coordination window first

powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\Documents\HarnessBootcamp\AI_Harness_Bootcamp\mission_flesh\p6\scripts\Update-P6.ps1" -Intent "Protect the regional coordination window; keep bridge clearance moving manually."

Let Goose finish without another prompt. The launcher opens the revised command center when it finishes.

If you need to reopen the revised page, paste:

Start-Process "$env:USERPROFILE\Documents\HarnessBootcamp\AI_Harness_Bootcamp\mission_flesh\p6\runs\current\command_center.html"

What you should see. The console ends with a line beginning P6 VERIFY PASS wave=2. The command center shows your exact intent and a visible What Changed section. NEW, CHANGED, CANCELLED, and UNCHANGED labels make the revision inspectable without opening another file.

Wave 2 is complete when the revised page explains what moved and why and the previous Wave 1 picture remains visible in its before-and-after view.

Stage 05 · Read the revision as the operator

Stay with the revised command center for one minute. Name what Goose coordinated, how your intent changed the page, and one real changing queue from your desk that could use this pattern.

P6 is complete when you can explain those three points from the dashboard without reconstructing the run from memory.

Before you move on

Confirm the current command center opens, the Wave 1 provisional allocation remains visible, your intent appears exactly, and What Changed explains the revision. Then save the short transfer above.

If you get stuck

  • The readiness check stops. Keep the exact message. Correct the named setup problem, then paste the complete Wave 1 command again.
  • The run stops early. Keep the console message. Paste the same complete command again; do not rewrite the prepared mission or source reports.
  • The dashboard does not open. Paste the complete Start-Process command from Stage 02. If the file is missing, keep the console message and ask for help.
  • You need a clean Wave 1 attempt. Paste the complete Wave 1 command again. The launcher rebuilds runs\current.
  • Wave 2 rejects the intent. Paste either complete Wave 2 command from Stage 04 again.
