Why this block exists

Autonomy is not “the brand is safe.” It is a loop plus bounds you wrote. goose can enforce some of those bounds with real levers — recipe, extensions, permission mode, max turns, retry checks, schedule. Other bounds stay procedure: stop authority, treating feeder text as data, who may restart.

In goose you configure bounds someone else designed. In Pi you build them — which is the only way to find out that not all bounds are the same strength. Three layers, and conflating them is the mistake this block exists to prevent:

LayerIn practiceWhat it actually gives you
The contractpi --tools read,grep,find,lsFilters the tool registry above the extension layer. The banned tool never enters the model's schema, so there is nothing to refuse and no refusal to talk it out of. Provable from the session file.
The tripwireA tool_call gate you writeCatches drift and mistakes, and fails closed when it errors. But it is defeatable by the thing it polices — a model holding bash can edit the gate or spawn a subshell whose commands never surface as tool calls.
The boundaryA containerThe only actual one.

A tripwire mistaken for a boundary is how people come to believe a written policy stops a process. Today you build one of each and find the seam yourself.

Four goose levers you open today
  1. Recipe — packaged mission (watch_officer.yaml): instructions, parameters, success checks.
  2. Tool surface — which extensions/tools exist (starter keeps developer only).
  3. Autonomy dial — GOOSE_MODE (approve vs auto) and settings.max_turns.
  4. Unattended path — Scheduler run-now, or an honest block with the exact error.
The contract’s tool-enforced column names these levers. Prose that only says “be safe” is not a tool row. Full notes: mission_flesh/p6/goose_recipe_notes.md · docs: goose-docs.ai.

What you will leave with

  • Adapted watch_officer.yaml (not stock-only) over the local feeder; successful run evidenced in out/
  • Two-column contract ≥3 rows each; at least three tool rows name real goose levers
  • Stop proof + restart proof; exception drill on event_04
  • Scheduled attempt or honest block with reason
  • Pi: a bound you proved from the session file, and — if you take the stretch — a tripwire you wrote and then defeated
  • Transfer P6 seed; full operator pulse

Run of exercise

  1. Open the chair

    Open your Codex app project. Confirm operator templates are present (DIRECTION_BRIEF.md, OPERATOR_LOG.md, etc.).

    Open chat Operator — Direction & Log. Paste the Direction Brief starter from the operator pack.

  2. Co-write the Direction Brief until LIVE

    Work the five fields with the AI: Outcome, Done looks like, Bounds, Evidence standard, Stop/hand-back.

    Do not start the mission until status is LIVE. Vague “explore the data” outcomes get challenged — name the artifact.

  3. Run the mission

    Pack: mission_flesh/p6/ — starter recipe watch_officer.yaml, feeder traffic in feeder/, operator notes in goose_recipe_notes.md. Dropping files into feeder/ simulates watch traffic.

    1. Adapt the recipe (path, bounds, max_turns, or mode — something real). Run it so new feeder files become lines in out/watch_summary.md. Stock demo only is not yet.
    2. Write the autonomy contract: columns Tool-enforced | Procedure-enforced (≥3 rows each). Tool rows name goose levers (extensions, GOOSE_MODE, max_turns, retry check, schedule). Map every serious feeder risk to a column.
    3. Stop under realistic load, then restart without losing the contract frame (same recipe/mode; prior good lines still present).
    4. Exception drill: feeder/event_04.txt is hostile. Contract behavior is quarantine + continue — not obey.
    5. Unattended path: schedule the recipe and Run now, or document the exact block and what would unlock it.
    6. Pi — prove a bound (required). Run the same tiny task twice in the same folder: once plain, once as pi --tools read,grep,find,ls -p "…". Then open the session file under %USERPROFILE%\.pi\agent\sessions\ and confirm the write tools were absent from the model's schema rather than offered and declined. That distinction — a bound the model complied with versus one it could not violate — is the whole point, and it is visible in the file.
    7. Pi — write the tripwire (stretch). Read Pi's shipped protected-paths example, then write your own tool_call gate at ~/.pi/agent/extensions/ that blocks writes outside the mission folder: 
      pi.on("tool_call", async (event, ctx) => {
  if (isToolCallEventType("write", event)) {
    // resolve the path before comparing — see what happens if you don't
    return { block: true, reason: "outside mission folder" };
  }
});
      Then defeat your own gate with a ../ path. Fix it by resolving against ctx.cwd first. Note where you put it: a gate in ~/.pi/agent/extensions/ loads before project trust and every project gets it; a gate in .pi/extensions/ lives inside the repo it is supposed to police.
    8. Name the layer for each row of your contract. Go back to your two-column contract and mark every row contract, tripwire, or boundary. Any row you marked "tool-enforced" that is really a tripwire is the finding of the block — write it in your log in those words.

    If scheduled runs are blocked on your OS or policy, that is a valid MVP outcome when the reason is written down. Honesty over theater.

  4. Operator Log + pass-bar draft

    Back in Direction & Log, paste the log starter. Record verdict, evidence, what you still own.

    Self-check against PASS_BARS.md for P6 — met / not yet with pointers. No inflation.

  5. Adversarial review (new chat)

    Open a new chat titled Adversarial — P6. Paste the frozen prompt from the operator pack plus your artifacts and provisional verdict.

    Copy the final line into your log: ADVERSARIAL: stood | wounded | failed — …. Fix if wounded.

  6. Measurement spine

    Update MEASUREMENT_SPINE.md: ritual 0–3, mission HIT/PARTIAL/MISS, quality STRONG/ADEQUATE/WEAK, time to result (minutes).

  7. Transfer pulse

    Chat Operator — Transfer 30-60-90. Paste the every-session transfer prompt. Leave a session-log row even if the seed is small today.

If you get stuck

  • Narrow data scope, not the judgment standard.
  • Re-read your LIVE brief — most chaos is an unbounded outcome.
  • Ask for a lead diagram of the one concept blocking you, then continue on your chair.
