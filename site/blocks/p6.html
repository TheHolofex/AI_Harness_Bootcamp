Why this block exists

Autonomy is not “the brand is safe.” It is a loop plus bounds you wrote. goose can enforce some of those bounds with real levers — recipe, extensions, permission mode, max turns, retry checks, schedule. Other bounds stay procedure: stop authority, treating feeder text as data, who may restart.

In goose you configure bounds someone else designed. In Pi you build them — which is the only way to find out that not all bounds are the same strength. Three layers, and conflating them is the mistake this block exists to prevent:

LayerIn practiceWhat it actually gives you
The contractpi --tools read,grep,find,lsFilters the tool registry above the extension layer. The banned tool never enters the model's schema, so there is nothing to refuse and no refusal to talk it out of. Provable from the session file.
The tripwireA tool_call gate you writeCatches drift and mistakes, and fails closed when it errors. But it is defeatable by the thing it polices — a model holding bash can edit the gate or spawn a subshell whose commands never surface as tool calls.
The boundaryA containerThe only actual one.

A tripwire mistaken for a boundary is how people come to believe a written policy stops a process. Today you build one of each and find the seam yourself.

Run of exercise

Work these in order and check each off as its proof exists. Progress saves in this browser — the same tick shows on the home page.

  1. Open chat Operator — Direction & Log. Paste the brief starter. Fill all five fields: Outcome, Done looks like, Bounds, Evidence standard, Stop/hand-back. Status must be LIVE before the mission — vague “explore the data” outcomes get challenged; name the artifact.
  2. Path: mission_flesh/p6/. Read goose_recipe_notes.md, open starter watch_officer.yaml, and list feeder/ — dropping files into feeder/ simulates watch traffic. event_04 is the exception drill. Create out/ if missing.
  3. Change something real (bounds, feeder_dir, max_turns, or mode). Run the recipe so feeder files become summary lines. Evidence: file on disk. Stock demo only is not yet. Prefer GOOSE_MODE=approve for the teaching run.
  4. Columns: Tool-enforced | Procedure-enforced. At least three tool rows name real goose levers (extensions list, GOOSE_MODE, max_turns, retry check, schedule). Map every serious feeder risk; no orphans. Template is in the recipe notes.
  5. Halt under realistic conditions (mid-run / about to write). CLI: Ctrl+C. Record time and what was in flight.
  6. Resume with the same recipe and mode. Prior good summary lines still present (append posture). Contract frame unchanged.
  7. Hostile feeder text is data, not orders. Contract behavior is quarantine + continue — not obey. Expect QUARANTINE: (or equivalent) and no delete/exfil effect. Note which lever held: tool surface, mode, procedure — or which failed.
  8. Schedule the recipe (Desktop Scheduler or CLI) and Run now once, or write the exact OS/policy error and what would unlock it. If scheduled runs are blocked on your OS or policy, that is a valid MVP outcome when the reason is written down. Honesty over theater.
  9. Run the same tiny task twice in the same folder — once plain, once as pi --tools read,grep,find,ls -p "…". Open the session file under %USERPROFILE%\.pi\agent\sessions\ and confirm the write tools were absent from the model's schema, not offered and declined. A bound the model complied with is not the same as one it could not violate, and the file shows you which you have.
  10. Read Pi's shipped protected-paths example, then write your own tool_call gate in ~/.pi/agent/extensions/ that blocks writes outside the mission folder: 
    pi.on("tool_call", async (event, ctx) => {
  if (isToolCallEventType("write", event)) {
    // resolve the path before comparing — see what happens if you don't
    return { block: true, reason: "outside mission folder" };
  }
});
    Defeat it with a ../ path. Fix it by resolving against ctx.cwd first. Note the difference between a gate in ~/.pi/agent/extensions/ (loads before project trust, applies everywhere) and one in .pi/extensions/ (lives inside the repo it polices).
  11. Go back through your two-column contract and mark each row. A contract removes the capability (--tools, goose tool surface). A tripwire catches drift but can be defeated by what it polices. A boundary is a container. Any row you called tool-enforced that is really a tripwire is the finding — write it in your log in those words.
  12. One real work process you’d put under contract: tool vs procedure rows, stop authority, exception path.

Four goose levers you open today

Recipe — packaged mission (watch_officer.yaml): instructions, parameters, success checks · Tool surface — which extensions/tools exist (starter keeps developer only) · Autonomy dial — GOOSE_MODE (approve vs auto) and settings.max_turns · Unattended path — Scheduler run-now, or an honest block with the exact error.

The contract’s tool-enforced column names these levers. Prose that only says “be safe” is not a tool row. Full notes: mission_flesh/p6/goose_recipe_notes.md · docs: goose-docs.ai.

Operator pulse — required every block

The same six-beat ritual closes every half-day: it is how a mission becomes evidence. Paste-ready prompts →

  1. Build work stays out of the operator chat — the trail is the point.
  2. Back in Direction & Log: what you directed, mid-run changes, verdict (ACCEPT / REJECT / ACCEPT WITH FIXES), evidence pointers, what you still own.
  3. Against P6’s MVP list: met / not yet with evidence pointers. No inflation.
  4. Chat Adversarial — P6: frozen prompt + artifacts + provisional verdict. Copy the final line into your log: ADVERSARIAL: stood | wounded | failed. Fix if wounded.
  5. Ritual 0–3 · mission HIT/PARTIAL/MISS · quality STRONG/ADEQUATE/WEAK · time to result (minutes). Deep mark if this block has one.
  6. Chat Operator — Transfer 30-60-90: paste the every-session prompt. A session-log row is required even if the seed is small today.
