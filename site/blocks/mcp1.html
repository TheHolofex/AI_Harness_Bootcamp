Use the full 30 minutes

00–07 min Name the boundary

Place MCP between a host and outside data or capabilities. Separate it from an in-process framework and from cross-organization agent delegation.

07–14 min Choose the surface

Distinguish tools, resources, and prompts by who initiates the interaction and whether the operation performs work or supplies context.

14–23 min See the production cost

Follow how tool descriptions, schemas, result size, routing, retries, and an oversized catalog consume context, time, and money.

23–30 min Operate the connection

Review least privilege, server provenance, untrusted results, observability, version control, and a deliberate disable path.

Carry four decisions into P3

Fit The connection must earn its overhead

Use MCP for a repeatable, shared capability boundary—not simply because a direct file read or ordinary API call feels less novel.

Context Every loaded tool has a cost

Expose only the relevant surface, retrieve each useful source once, and keep output to what the work product actually needs.

Trust Metadata describes; code enforces

Descriptions, annotations, schemas, and server instructions can guide the host, but they do not prove that code or returned content is safe or true.

Operations A connection has an exit

Know what started, what it can reach, which calls ran, what failed, and exactly when the connection will be disabled or revoked.
