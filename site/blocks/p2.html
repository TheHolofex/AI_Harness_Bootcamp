Make the system carry the method

P1 proved that a serious work product can be regenerated from controlled sources. P2 makes that ability durable. You will move the procedure into a focused skill, keep the always-on instructions short, install a reviewed plugin that supplies a deterministic release hook, use read-only specialists where separate context helps, and use MCP only where current external information is actually required.

The result is not a component collection. It is one working production line for the P1 daily brief. Every addition has a named job, a cost, an evidence path, and a way to turn it off.

What you will leave with

  • A clean personal project that contains the P1 source packet, a short project policy, and one focused daily-brief skill
  • A course-distributed plugin whose reviewed Stop hook checks the saved product and writes a release receipt
  • Evidence, documentation, and review agents, all pinned to gpt-5.6-terra, run under a read-only parent turn, and limited to two open agent threads
  • A real release-ready daily brief, its source map, configuration evidence, quality-gate receipt, and observed run cost
  • An active-component manifest that shows what stays on, what remains available on demand, and what is disabled until a named need appears

Put each behavior where it belongs

The strongest harness is not the one with the most parts. It is the one that loads each necessary behavior at the narrowest useful scope.

SurfaceWhen it loadsUse it forDo not mistake it for
AGENTS.mdEvery turn in scopeShort project conventions, constraints, commands, and ownershipA storage bin for every procedure
SkillWhen named or matched by its descriptionOne reusable workflow with inputs, decisions, output, and stopping rulesDeterministic enforcement
HookAt a lifecycle eventA mechanical check that must run even when the model forgetsA complete security boundary or another prompt
SubagentWhen delegatedIsolated read-heavy research, tests, or review with a compressed returnA second independent engine or free compute
MCPWhen a connected capability is neededLive external data or controlled action with a declared tool surfaceA workflow, a trust seal, or another opinion
PluginWhen installed and enabledDistributing stable skills, hooks, MCP configuration, and related assetsA new reasoning layer
Config + approvalAt project/session runtimeModel, concurrency, sandbox, permissions, and tool policyEvidence that the output is correct

Six engineering rules that save real work

ContextKeep always-on guidance thin

Skill names and descriptions can load before their bodies. A bloated catalog still consumes context and may be shortened or omitted. Narrow descriptions are routing contracts.

GuaranteeUse code for must-run checks

A skill can tell the model to check. A hook can make the check run at Stop. Current Codex hooks execute reviewed command handlers; they are useful guardrails, not complete containment.

TopologyParallelize reads, serialize judgment

Run independent evidence and documentation research together. Review only after a candidate exists. Keep one writer so the product has one owner.

CapabilityGive MCP one bounded job

The Docs MCP server verifies changing product behavior from primary documentation. It is read-only here; no business system or write-capable tool is added merely to demonstrate a connection.

DistributionPackage only stable controls

Your daily-brief skill stays local while it changes. The course quality gate is already stable and shared, so it earns plugin packaging.

ReleaseMeasure the integrated outcome

Record acceptance, time, turns, approvals, repairs, quality-gate result, and residual risk from the actual product run.

Stage 05 · Run the integrated production line

This is the serious product run. One chat moves through three purposeful turns: a write-capable candidate, a read-only review, then a write-capable release that arms the hook only after every required artifact exists. One focused hook continuation is allowed; a second failure remains a HOLD.

Create the production chat from the beginning:

  1. In P2_Control_Plane, click New chat
  2. Rename it P2 — Daily Brief Release
  3. Select GPT-5.6 Terra and Ask for approval
  4. Write the local start time in HARNESS_PROFILE.md

First produce the candidate while the gate remains disabled:

Use $daily-brief-release to regenerate today's daily status brief through the
saved-candidate phase only.
Use the declared P1 source set, out/EVIDENCE_MAP.md, and HARNESS_PROFILE.md.
The main thread owns every write. Save the candidate at the declared final path,
but keep P2_CONTROL_PLANE.json disabled. Do not spawn the reviewer, do not claim
release, and do not estimate hidden usage or cost. Stop when the candidate is
ready for an independent review.

Run the independent review under a real read-only boundary:

  1. Keep P2 — Daily Brief Release open
  2. Change the permission control to Read only
  3. Paste the request below
Run the decision_reviewer against out/FINAL_DAILY_BRIEF.md, the declared P1
sources, HARNESS_PROFILE.md, and P2_CONTROL_PLANE.json. Wait for its PASS or HOLD
result and return that result exactly. Do not write or change a file. Close the
completed reviewer thread before you stop.

Release the reviewed product and arm the gate at the safe moment:

  1. Change the permission control back to Ask for approval
  2. Paste the release request below
Use the decision_reviewer result from the previous turn. Save that exact result
to out/DECISION_REVIEW.md. Make only material, source-supported repairs.
Complete out/RUN_RECEIPT.md with observed time, turns, subagent runs, approvals,
repairs, and visible usage or "not exposed".

Confirm every required release file exists. Then, as the last configuration
change before stopping, change only enabled from false to true in
P2_CONTROL_PLANE.json. Do not weaken the contract. Stop for the deterministic
release gate.

If the hook continues the turn, read its named failures and watch the one repair pass. When the turn ends, open:

  • out/FINAL_DAILY_BRIEF.md — the actual work product
  • out/DECISION_REVIEW.md — the independent PASS or HOLD result and material findings
  • out/QUALITY_GATE_RECEIPT.json — status, each check, timestamp, and product hash
  • out/RUN_RECEIPT.md — observed time, turns, subagents, approvals, repairs, and visible usage or not exposed

Release requires a PASS receipt and your own reading of the brief. The hook proves its checks ran; it does not prove that the judgment is wise.

KEEP, REVISE, or LEAVE OFF UNTIL NEEDED. Include its job, context or token cost,
permission surface, evidence, disable path, and residual risk.

Keep the local daily-brief skill editable. Do not package it for distribution

Operating notes for real harnesses

Use these after the core run when you decide what belongs in a personal setup, a repository, or a team-distributed plugin.

Cost and control signals

Every task receives a long policy blockConditional procedure sits in always-on instructionsKeep the project rule short and move the workflow into one focused skill
A skill fires on unrelated workDescription states a topic, not a trigger boundaryFront-load the exact job and add a clear non-trigger condition
The model sometimes skips a mandatory checkEnforcement lives only in proseUse a reviewed deterministic hook or external check at the relevant event

MCP adds many tools but little evidenceConnection chosen before the work needAllow only the server and tools the product requires; disable the rest

Install another plugin only when the desk supplies the job

Start with the real information or action the product lacks. An available plugin is a candidate, not a reason to widen the harness.

Real missing jobCandidate capabilityProof that earns installationLeave it off when

Controlled documents outside the projectAn approved Google Drive or SharePoint pluginOne named document is retrieved with owner, provenance, and access boundary visibleThe connector would expose a broader drive or site than the product needs

Before installing, inspect bundled skills, MCP or connector tools, hooks, authentication, data boundary, approvals, and uninstall path. Install from the approved source, start a new chat, prove the serious outcome above, and then keep or remove it. Some connector-backed plugins are unavailable under API-key sign-in because their authorization flow is not supported. Verify that constraint; do not install a substitute just to fill the slot.

When a real release decision needs stronger measurement

The core P2 result answers whether this integrated control plane produced this product inside its contract and operating budget. If a consequential deployment decision requires a broader capability claim, use Build a Decision-Grade Evaluation to define the claim, risk coverage, independent decision set, and invalidation rules.

If the decision specifically depends on run-to-run stability, use Measure Reliability Across Repeated Runs after a valid A/B comparison exists. It shows how to pair conditions, expose order effects and spread, and keep the conclusion no larger than the observed trials.

Before you move on

The final daily brief, independent review, PASS receipt, and active-component manifest exist; observed time, turns, approvals, repairs, and residual risk are recorded; the hook is disarmed; and each component has an enacted keep, revise, or leave-off decision.

If you get stuck

  • The P2 folder already exists. Open and continue that project, or move it to a dated archive. The bootstrap will not overwrite it.
  • The skill is missing. Confirm the file is under .agents\skills\daily-brief-release\SKILL.md, then restart the app and reopen the project.
  • The plugin does not appear. Confirm .agents\plugins\marketplace.json and plugins\p2-release-control exist at the P2 project root, then restart the app.
  • The hook is skipped. In a terminal opened at P2_Control_Plane, run codex, type /hooks in the CLI, inspect the Stop handler, and trust the current definition. A changed command requires new trust.
  • The Docs agent has no MCP tool. Confirm its TOML contains https://developers.openai.com/mcp, read the visible connection error, and fix that connection. Do not substitute memory.
  • A subagent edits files. Stop it. A role file does not override the parent turn's live permission profile. Set the parent to Read only, rerun the bounded research or review, close the completed thread, then use a separate Ask for approval main-writer turn to save the return.
  • The receipt stays FAIL after one repair. HOLD. Read the failing checks and ask the operator whether to repair the product, change a genuinely wrong contract, or stop. Do not loop or lower the bar.
