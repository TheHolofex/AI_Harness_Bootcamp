Use the full 30 minutes

00–07 min Start with load timing

Separate what must always be present from what should load only for a matching job, event, agent, or external capability.

07–15 min Place the behavior

Use instructions for durable guidance, a skill for reusable procedure, and a hook when the check must run whether the model remembers it or not.

15–23 min Add capability with bounds

Use subagents for isolated work and compressed returns; use MCP for live data or controlled action; keep approvals and least privilege visible.

23–30 min Distribute only what is stable

Keep a personal workflow as a local skill while it changes. Package it as a plugin only when installation and reuse by other people are real needs.

Carry this map into the P2 build

Always onAGENTS.md

Short project conventions, constraints, commands, and review expectations.

On demandSkill

A focused workflow whose description states exactly when it should and should not load.

On eventHook

A reviewed command that deterministically checks or blocks at a lifecycle point.

On delegationSubagent

A narrow worker with its own context and token cost, returning a concise result to the main writer.

On capabilityMCP

A bounded tool surface over local data or an external capability, with provenance, permissions, and an exit.

On installationPlugin

A distribution bundle for stable skills, hooks, MCP servers, or other shared capability.

The placement testWhat job does this component do, when must it load, what does it cost, what does it enforce, and how is it disabled? If those answers are vague, do not add the component yet.
