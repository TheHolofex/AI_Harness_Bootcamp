Why this block exists

A harness is the setup around a model that lets it act: tools, files, permissions, instructions, and your accept/reject loop. In First Light, you will feel that loop before we name every part of it.

You will use two chats. Operator — Direction & Log holds the work specification and final release record; Build — B1 First Light reads the reports and changes the viewer. The observable browser checks decide whether the result is ready.

What you will leave with

  • Save a complete B1 work specification before the build
  • Ship a working map from the synthetic report folder (timeline and filters)
  • Run an exclusion check and a current-source refresh
  • Leave a release note, status, residual risk, and reusable workplace rule

Before you start

  • B0 · Pre-work Install Clinic complete
  • Four harness check files visible in Documents\HarnessBootcamp\prework-smoke
  • The course repository cloned into Documents\HarnessBootcamp

Lead operate-along

The lead runs this same page on screen — project opened from the beginning, work specification saved, viewer built, and browser checks narrated. You still run your own chair, and you check a box when you finish the step, not when you watch it.

B0 is the gate Start First Light after the B0 checks pass: the four harness check files exist, the keys work in a fresh shell, and the course repository is on disk. If one of those is missing, return to the install clinic checklist before starting this mission.

Run of exercise

Build one working viewer, run the checks yourself, and leave a release record another person can follow. Check an item only when the named file or observed result exists.

Stage 01 · Open the project and set the work specification

The course project is the folder the assistant can work in. Start in the standing operator chat, confirm the project root, then save the specification that will govern the build.

Start in the ChatGPT desktop app:

  • Open ChatGPT from the Windows Start menu. Use the top-left switcher to select Codex if needed
  • Click Open project and choose Documents\HarnessBootcamp\AI_Harness_Bootcamp
  • Open Operator — Direction & Log from the sidebar
  • If it is missing, click New chat, rename it Operator — Direction & Log, and pin it if Pin appears
  • Select the instructor-named course model, or keep the visible default if none was named
  • Confirm the permissions control under the message box says Ask for approval

Paste this into Operator — Direction & Log:

List the top-level contents of operator/ and mission_flesh/. Names only.

You should see the operator files plus b1/ and p1/ through p8/ inside mission_flesh/. If those folders are missing, reopen the project at AI_Harness_Bootcamp itself.

Now save the B1 work specification in the same chat:

Read operator/DIRECTION_BRIEF.md and replace its active brief with this B1 specification.

Outcome: a local timeline-and-filter viewer at mission_flesh/b1/first_light/index.html.
Done looks like: the page opens offline, shows the six report_*.md files, orders dated
events correctly, handles the undated report explicitly, and has two working filters.
Bounds: read mission_flesh/b1/reports/; ignore DELTA_new.md until the update step; write
only under mission_flesh/b1/first_light/.
Evidence standard: I will open the page and check report count, time order, two filters,
one named exclusion, and the later DELTA update myself.
Stop / hand-back: propose the report data shape and source list before writing; stop if
the source count or an undated-report rule is unclear.

Write these five fields, set Status to LIVE, and report the exact file section changed.
Do not start the build in this chat.
  1. operator/DIRECTION_BRIEF.md names the viewer, source boundary, acceptance checks, and proposal stop before any build work begins.

Read the input before the assistant turns it into a data model. The source set contains six current reports and one later update.

Run this in PowerShell:

Get-ChildItem "$env:USERPROFILE\Documents\HarnessBootcamp\AI_Harness_Bootcamp\mission_flesh\b1\reports"

You should see six report_*.md files plus DELTA_new.md. The reports include a time, summary, and other fields, but report_06_export_eu.md has no DTG. Leave DELTA_new.md out of the first build.

  1. You saw six current reports, the held-back update, and the report with no DTG. If the listing differs, fix the project or repository path before building.

Stage 03 · Approve the data shape and build

Create the build chat in the Codex app:

  • Click New chat and rename it Build — B1 First Light
  • Confirm the open project is AI_Harness_Bootcamp and permissions say Ask for approval

Paste this into Build — B1 First Light:

Read the reports in mission_flesh/b1/reports/. Use only the files named report_*.md —
ignore DELTA_new.md; it arrives later as a live update.

First, propose a minimal data shape for one report (time, tag or type, summary, source file)
and show me the list of reports you found. Wait for my OK before building anything.

Then build a single-page viewer at mission_flesh/b1/first_light/index.html with:
- a timeline that orders or filters events by time
- at least two filters that change the visible set
Embed the report data directly in the page so it opens by double-click, fully offline —
no fetch, no server, no external libraries.

When it is built, tell me the exact file path and what I should ask you to do
after a report is added or removed.

Review the proposal before allowing file writes:

  • Confirm it found exactly six report_*.md files
  • Confirm the shape includes time, tag or type, summary, and source file
  • Confirm it states how the undated report will appear
  • If a condition fails, name the correction and ask for a revised proposal
  • If all conditions hold, tell the build chat to proceed

Approve the file writes when the app asks. The acceptance point is the proposal you inspected, not a canned approval.

  1. The accepted data shape covers all six current reports and the build wrote mission_flesh/b1/first_light/index.html.

Stage 04 · Run the viewer checks

Open the viewer from PowerShell:

Start-Process "$env:USERPROFILE\Documents\HarnessBootcamp\AI_Harness_Bootcamp\mission_flesh\b1\first_light\index.html"

The browser should show all six current reports and no DELTA item. If the page is blank or a file is missing, give the build chat the exact symptom and rerun this check after the repair.

  1. The file opens directly in the browser and displays the complete initial set.

Check the timeline in the browser:

  • Use the timeline control to order or filter events by time
  • Confirm the convoy log (0340Z) is earliest and the restore report (0510Z) is latest
  • Record where the undated export ticket appears
  1. The dated endpoints are correct and the undated report follows an explicit, observable rule.

Check both filters in the browser:

  • Count the visible reports, apply the first filter, and confirm the resulting set matches its label
  • Clear it and confirm the full set returns
  • Repeat with the second filter
  1. Each filter changes the visible set as labeled, and clearing it restores all six reports.

Stage 05 · Check a report that must be excluded

Run one exclusion check in the browser:

  • Apply a filter that must exclude a report you can name — for example, a movement filter that must not show the Relay-7 outage report
  • Confirm the named report is absent
  • Clear the filter and confirm it returns
  1. The named report stays out of the filtered view and returns when the filter is cleared.

Stage 06 · Refresh the viewer with a new report

Return to Build — B1 First Light and paste:

A new report just landed: mission_flesh/b1/reports/DELTA_new.md.
Add it to the viewer's data and rebuild mission_flesh/b1/first_light/index.html.
Tell me exactly what changed in the data.

Reload the viewer in the browser:

  • Press Ctrl+R
  • Confirm a seventh event appears at 2026-08-10 0600Z
  • Confirm it appears after the restore report

If the event does not appear, report the observed result to the build chat and rerun after the repair. If the refresh remains broken, record that exact result and hold the release.

  1. The seventh event appears in the correct place, or the exact failure is recorded and the release is held.
