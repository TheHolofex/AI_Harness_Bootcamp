Why this block exists

A harness is the setup around a model that lets it act: tools, files, permissions, instructions, and your accept/reject loop. In First Light, you will feel that loop before we name every part of it.

You will work in more than one chat today, and the split is deliberate. Build work — the machine reading files, writing code, rebuilding a page — runs in its own chat. Direction and verdicts — the brief you write before the run, the log you write after, the lesson-outcome checklist, the attack on that list — run in a separate operator chat. Keep them apart and your log’s evidence pointers stay checkable by someone who was not in the room. Let them merge and the chat that helped you build is the same chat you ask whether the build was any good; it will tell you yes, and you will have no trail that says otherwise. Each paste below names the chat it belongs in — follow the names and the split takes care of itself.

What you will leave with

  • Co-write a full LIVE Direction Brief (five fields)
  • Ship a working map from the synthetic report folder (timeline and filters)
  • Run a negative check and an update proof (or honest break + redirect)
  • Explain the harness loop from this run; complete log, adversarial, measure, transfer

Stage 06 · Prove what must not appear

Positive checks show the instrument can succeed; a negative check shows it can be trusted. You prove an absence: a slice of the view where a report you can name must not show up.

Now in the browser, on the viewer page:

  • Apply a filter that must exclude a report you can name — for example, a movement or convoy filter that must not show the Relay-7 outage report
  • Confirm the excluded report is absent from the visible set — actually look for it
  • Clear the filter and confirm it comes back

Your tag names may differ from this example — the machine chose them from the data shape you accepted. The move is the same regardless: name the report that must stay out, look for it, and see with your own eyes that it isn’t there. If it leaks through, you have found a real defect before it found you.

  1. Proof: a must-not case you verified yourself — the named excluded report stayed out of the filtered view and returned when cleared. “It probably filters right” is not a verification; the absence has to be observed.
