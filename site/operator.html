Production workflow reference

The module page is the main path. This reference explains the few moves that consistently improve AI-assisted work: specify the deliverable, build it, inspect real evidence, make the release decision, and leave a usable handoff.

Run the module, not this page Your current module contains the exact prompt, command, acceptance checks, and recovery. Use this page only when you need the reasoning behind a move.
One module · one task · one model Use the exact chat names on the module page. Start a fresh named chat for a different build, retry, independent review, isolated test case, project boundary, or model. Saved files carry the handoff; chat history is disposable. The only planned cross-module chat is P7–P8 — 30/60/90 Plan, and it is reused only while the planning role and model match.

1 · Before work starts

Specify the deliverable

Write only the requirements that change the build: what must exist, who uses it, which sources are allowed, what must never happen, how you will inspect the result, and when the AI must stop for you. From P1 onward, the module supplies most of this; make the learner-owned choices and start.

2 · Produce the artifact

Build in the real surface

A serious result lives outside a persuasive chat. Save the page, workflow, configuration, score sheet, comparator, policy, or report at the path the module names. Keep generated output separate from the criteria and answer key used to judge it.

3 · Inspect the result

Use the strongest available check

Prefer direct evidence over another opinion: open the artifact, run the saved command, walk the citation, compare against the source, inspect the diff, score the fixed cases, or confirm the held row never reached the irreversible write. Check the failure mode that matters for this product, not a generic classroom trick.

Use a fresh reviewer only when an important judgment remains after those checks. Give it frozen inputs and ask for criterion · evidence · status · severity · required fix. A useful review changes the artifact or release decision; mandatory disagreement does not improve either.

4 · Act on the finding

Release, fix, or hold

Release when the listed checks pass. Fix before release when the defect is bounded and repairable now. Hold when a material claim, control, or source remains unresolved. The status follows evidence; it is not a grade on effort.

5 · Make the result reusable

Leave one handoff

Record the artifact path, release decision, strongest evidence, remaining risk and owner, and the next run or update path. Add one rule you will reuse at work. P7 and P8 turn those concrete rules into the 30/60/90 plan; earlier modules should contribute a direct seed, not another interview.
