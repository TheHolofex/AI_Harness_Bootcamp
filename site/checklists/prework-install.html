Pre-work hub

Before you begin

  1. Complete this before Monday Block 0. Monday morning is for First Light, not install. Plan a focused evening or weekend block — often about 2–4 hours, depending on your machine and accounts.

    Seat credentials (ChatGPT/Codex, Claude, any class API keys) come from the course. Install the apps even if sign-in waits on seats — finish login as soon as seats land.

  2. Create a notes file on your machine (or copy prework/SETUP_LOG.md from the repo). After each major step, write:

    • Result (ok / failed)
    • Any error text
    • What you tried
    • Rough time spent

    You will bring this log Monday. At least one real failure + fix should appear in it.

0. Baseline machine

  1. Press Win + R, type winver, Enter. You want Windows 11.

    Run Windows Update and install pending updates if you can. Record the version string in your setup log.

  2. Open File Explorer → This PC. Check free space on your system drive. Agent tools, Node, and caches add up. If you are tight on space, free some before continuing.

  3. You need enough rights to run installers. If this is a corporate-locked laptop, escalate to IT/support now — do not wait until Sunday night.

    In your log: admin yes/no · corporate managed yes/no.

  4. Open your usual browser. You will complete sign-in flows for Codex and Claude. If the browser is blocked from accounts, fix that before installing apps.

1. PowerShell readiness

  1. Start menu → type PowerShell → open Windows PowerShell (user session is fine). You should see a prompt like PS C:\Users\YourName>.

  2. Paste and run:

    Get-ExecutionPolicy -List

# If scripts are blocked, prefer user scope (not machine-wide):
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

    Then confirm:

    Get-ExecutionPolicy -Scope CurrentUser

    You want RemoteSigned or less restrictive.

    If group policy blocks this: copy the error into your setup log and contact support before Monday. Do not keep pushing blindly.

2. Git for Windows

  1. In PowerShell:

    winget install --id Git.Git -e --source winget

    If winget is missing: update App Installer from the Microsoft Store, or install Git from the official Git for Windows site and note that path in your log.

  2. PATH changes apply to new terminals. Close PowerShell completely, open a new window.

  3. Run:

    git --version
Test-Path "C:\Program Files\Git\bin\bash.exe"

    You want a version line from git, and preferably True for the bash path. If bash is elsewhere, write the real path in your log — you will need it for Pi.

3. Node LTS + Python

  1. winget install --id OpenJS.NodeJS.LTS -e --source winget
winget install --id Python.Python.3.12 -e --source winget

    Accept installer prompts. If Python offers “Add to PATH,” enable it.

  2. Close and reopen PowerShell so PATH updates.

  3. node -v
npm -v
python --version
pip --version

    If python fails, try:

    py -3 --version

    Record versions in your setup log. All four should respond (or py launcher equivalent for Python).

4. OpenAI Codex app (primary home)

  1. Install via the official Windows path for your course date (Microsoft Store and/or OpenAI’s current Windows app instructions).

    What you want: the app launches from the Start menu.

  2. Use the ChatGPT/Codex seat staff issued. If seats are not ready yet, leave the app installed and return to this step when credentials arrive — then check this box.

  3. Create:

    Documents\HarnessBootcamp\prework-smoke

    You will reuse this folder for all four agents.

  4. This course targets vanilla Windows without WSL. In app settings, prefer the Windows-native agent path. Note sandbox/approval mode (Ask vs higher access) in your log so you know what you clicked.

  5. Open the prework-smoke project/folder in Codex. Ask the agent to create hello.txt with a short line of text. Approve the action if prompted.

    Pass only if the file exists in Explorer — not only if the chat says it did.

    Optional rename later to from-codex.txt for the health check naming scheme.

  6. If elevated sandbox fails, try unelevated / document the error. You still need folder write proof. Put the workaround in your setup log.

5. Claude Desktop + Code tab (second engine)

  1. Download from the official Claude / Anthropic Windows download page used by the course. Run the installer. Launch Claude from the Start menu.

  2. Complete browser sign-in. If you see upgrade/403 on Code, your seat tier or login is wrong — fix with staff before Monday.

  3. In Claude Desktop, open Code (not only Chat). This is the second engine for twin-engine day.

  4. If you installed Git after Claude, fully quit Claude and reopen. Local Code sessions expect Git for Windows on this course path.

  5. Environment: Local. Select folder Documents\HarnessBootcamp\prework-smoke. Notice permission mode (Manual / Accept edits / etc.).

  6. Ask Claude Code to create from-claude.txt (or any uniquely named file). Approve as needed. Confirm the file in Explorer.

6. Pi (bare-loop tool)

  1. Pi on Windows expects a bash shell. For most people that is Git Bash.

    Docs: pi.dev Windows setup.

  2. Follow the install steps on pi.dev for Windows. Record the exact method in your setup log (installer name / command).

  3. If Pi cannot find bash, set shellPath (or equivalent) to:

    C:\Program Files\Git\bin\bash.exe

    Use your real path if Git is installed elsewhere (from your earlier Test-Path / locate step).

  4. Open the project directory and run a harmless command (for example list files, or create from-pi.txt). Confirm Pi starts cleanly.

    Write proof in Explorer when you create a file.

7. goose

  1. Use current goose docs for Windows (desktop installer and/or PowerShell/Git Bash CLI install). Record desktop vs CLI in your log.

  2. App starts from Start menu, or goose responds in the terminal.

  3. On first run, goose asks for provider setup. Use the provider/seat staff specified for class.

    If you hit keyring errors on Windows, follow goose’s Windows notes (env var / disable keyring) and log the workaround.

  4. Complete one trivial successful session or sample recipe. Then create from-goose.txt in prework-smoke (via goose or manually after a successful tool write) so health check naming is consistent — prefer a real goose write when the tool can touch the folder.

8. Obsidian + n8n

  1. Download from the official Obsidian site. Install and launch. Create any local vault to prove it opens (class vault arrives Wednesday).

  2. Use the method staff specify for your cohort (local npm global, desktop build, or other docker-free path). If npm-based, a common pattern looks like:

    npm install -g n8n

    Only use commands staff confirm for your cohort — versions change.

  3. Start n8n, open the local URL it prints (often localhost with a port). Confirm the editor loads. Know how to stop it (terminal Ctrl+C or app quit).

9. Course repo / operator pack

  1. When staff share the link, get the repo onto your machine (GitHub clone or zip). Example:

    git clone https://github.com/TheHolofex/AI_Harness_Bootcamp.git
cd AI_Harness_Bootcamp

  2. Copy the standing files from operator/ (Direction Brief, Operator Log, Pass bars, Adversarial, Measurement, Transfer) into the project folder you will use in Codex all week.

  3. Read student_pack/README.md and open the local course site:

    python3 -m http.server 8080

    Then visit http://localhost:8080/site/ (from repo root). Note thread names: Direction & Log · Adversarial · Transfer.

10. Finish through health check

  1. Open Health Check checklist and run it end-to-end on this machine.

    You are not done until the health check is GREEN, or YELLOW with a staff-approved workaround documented — or explicitly waived in writing.

  2. Screenshots or notes: four agent files in Explorer, versions, seat sign-in, gate color (GREEN/YELLOW/RED). Pack laptop + log for Monday.

Rescue paths (only if something failed)

  1. Update App Installer from Microsoft Store, or install Git/Node/Python from official .exe installers. Log which path you used.

  2. User-scope RemoteSigned is the preferred fix. If corporate policy blocks it, escalate early with the error text.

  3. Still prove folder write. Put the exact error and workaround in your log.

  4. Confirm seat tier and login. Fully quit and reopen Claude after installing Git.

  5. C:\Program Files\Git\bin\bash.exe

  6. Follow current goose Windows notes (environment variable or disable keyring). Log the fix.

  7. Imaging is not the default rescue. Owning the install is the point — but locked machines need staff/IT early.
