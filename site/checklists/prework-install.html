Before you begin

  1. Finish before Monday's first session. Most people need two to four hours; a corporate-managed laptop can take longer, because policy blocks turn up one at a time rather than all at once.

    Start early enough that you can raise a blocker and still get an answer. Sunday night is the most reliable way to arrive stuck.

  2. Copy prework/SETUP_LOG.md, or open any notes file. After each section, write down the result, any error text, what fixed it, and roughly how long it took.

    Copy error messages exactly rather than paraphrasing — the precise wording is usually the thing that identifies the problem. A carefully recorded failure is worth more on Monday than a clean install with no trail behind it.

  3. You need an OpenAI key starting sk-proj-, an xAI key starting xai-, and an Anthropic key starting sk-ant-api03-.

    If any are missing, say so in the pre-work channel now and start installing anyway. The first five sections need no keys at all, so you can get most of the machine ready while you wait.

  4. Foundations first: a terminal, a package manager, Git, then Node and Python. Then your three keys. Then six tools that use them.

    All of it is driven from one window — a PowerShell terminal. You'll open it in step 9 and stay there for the rest of this guide.

    The Codex app is your home for the week. OpenCode is the second harness you'll run the same brief through on Tuesday. Pi is a minimal, extensible coding harness — small defaults, then skills, packages, and tree-shaped sessions when you need more. goose is a local agent platform: packaged recipes, a tool surface (extensions), an autonomy dial (mode and max turns), and an unattended path (schedule) — Thursday’s autonomy-contract vehicle. 0 · Baseline machine

  1. Press Win+R, type winver, press Enter. Note the version in your log.

    Then open PowerShell and check the architecture, because two tools here have no 32-bit build:

    [Environment]::Is64BitOperatingSystem

    You want True. Install any pending Windows updates now — doing it later tends to interrupt something mid-install.

  2. Snapdragon and other ARM Windows laptops — often sold as Copilot+ PCs — can't run this stack. OpenCode fails to start on Windows ARM64, and goose publishes no ARM build at all.

    $env:PROCESSOR_ARCHITECTURE

    AMD64 means you're fine. ARM64 means flag it today, before installing anything else. That's a machine question rather than something you can solve at the keyboard, and it needs lead time.

  3. Open This PC and check free space on C:. The tools themselves are modest, but Node's dependency trees and the model caches add up faster than you'd expect.

  4. Most steps install into your own user profile and need no administrator rights. Three do prompt for elevation: Git, Node, and Codex's sandbox setup.

    If your laptop is corporate-managed and you can't approve an elevation prompt, raise a ticket today. This is the blocker that most reliably costs people their Monday, and it's the one you can't work around from your own seat.

1 · Terminal and PowerShell

  1. Press Win, type Terminal, press Enter. Do not choose "Run as administrator" — the installers below ask for elevation individually when they genuinely need it, and running the whole session elevated can put things in the wrong place.

    Avoid the Start menu entry labelled Windows PowerShell (x86). That's a 32-bit host, and some installers refuse to run in it even on a 64-bit machine.

    This window is where every command in this guide goes. Windows ships three terminals that look similar, and commands are not interchangeable between them. Tell them apart by the prompt:

    WindowPrompt looks likeUse it for
    PowerShellPS C:\Users\you> — note the PSEverything in this guide
    Command PromptC:\Users\you> — no PSNothing here, unless a rescue step says so
    Git Bashyou@machine ~ $ — a $, and / in pathsOne goose fallback in step 55

    Confirm you're in the right one:

    $PSVersionTable.PSVersion

    A version number means PowerShell. An error means you're somewhere else — close it and open Terminal again.

    Three errors later in this guide mean "wrong window" rather than "broken install", and they're worth recognising now:

    • 'irm' is not recognized — you're in Command Prompt, not PowerShell.
    • The token '&&' is not a valid statement separator — a Command Prompt or Git Bash style command pasted into PowerShell.
    • A parameter cannot be found that matches parameter name 'fsSL' — a Mac or Linux curl command pasted into PowerShell, where curl means something different. This is exactly what happens if you try OpenCode's website installer.
  2. $PSVersionTable.PSVersion

    Stock Windows 11 shows 5.1. That's expected, and it's enough for everything in this guide.

    PowerShell 7 is a separate, newer shell that installs alongside 5.1 rather than replacing it. It's optional. If you want it:

    winget install --id Microsoft.PowerShell --source winget --installer-type wix --accept-source-agreements --accept-package-agreements

    The --installer-type wix matters. Without it you get a sandboxed build that can't change some settings you may need later.

  3. Windows blocks PowerShell scripts by default. Several installers below — and npm itself — are scripts, so this has to change or they fail with an error that reads like a permissions problem but isn't one.

    Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

    Answer Y if prompted. RemoteSigned means scripts you wrote run freely while downloaded ones must be signed; CurrentUser means it applies to your account only and needs no admin rights. Then check what actually took effect:

    Get-ExecutionPolicy -List

    Look at the MachinePolicy and UserPolicy rows. If either shows anything other than Undefined, your IT department sets this centrally and your change is ignored no matter what the command reported. Log the exact output and ticket IT today.

2 · winget, the package manager

  1. winget is Microsoft's built-in package manager. It downloads and installs software from a command instead of a website, which is why several steps below are one line long. It ships with Windows 11.

    winget --version

    A version number means you're set. 'winget' is not recognized means go to the next step.

  2. Skip this if the previous step printed a version. Otherwise try these in order, checking winget --version in a new window after each.

    Re-register the package — on a freshly imaged machine it sometimes just hasn't finished registering:

    Add-AppxPackage -RegisterByFamilyName -MainPackage Microsoft.DesktopAppInstaller_8wekyb3d8bbwe

    If that doesn't do it, use Microsoft's repair module:

    Install-PackageProvider -Name NuGet -Force | Out-Null
Install-Module -Name Microsoft.WinGet.Client -Force -Repository PSGallery | Out-Null
Repair-WinGetPackageManager -Force -Latest

    If winget still refuses, don't fight it. Every tool below has a direct-download alternative — note it in your log and carry on.

  3. The first time winget runs it stops and asks you to accept its source terms. Get that out of the way now, so a later install doesn't appear to hang when it's really waiting for a keystroke you can't see.

    winget source update --accept-source-agreements

3 · Git for Windows

  1. Git tracks changes to files, and you'll use it to fetch the course repository. It also installs Git Bash, a second kind of terminal that some tools reach for behind the scenes — which is the real reason Git comes this early.

    To be clear about what you have to learn: you type everything in PowerShell. Git Bash is a dependency, not a second shell to get fluent in. Pi is the one tool that genuinely can't run without it, and it calls it for you. The only time you'd open Git Bash yourself is one goose fallback in step 55.

    winget install --id Git.Git -e --source winget --scope machine --accept-source-agreements --accept-package-agreements

    Approve the elevation prompt. --scope machine puts Git at a predictable path other tools know to look in; without it Git can land somewhere they won't find. If winget isn't available, download from git-scm.com/download/win and accept the installer defaults.

  2. Installers record new programs in a Windows setting called PATH, but a terminal reads PATH once when it opens and never again. Your current window will insist Git isn't installed.

    This causes more "it didn't install" reports than every other cause combined, and it recurs after every install below. Build the habit now: install, close, reopen, verify.

  3. git --version
Test-Path "C:\Program Files\Git\bin\bash.exe"

    You want a version number and True. Record that path in your log — Pi asks for it if it can't find it on its own.

    If Test-Path returns False, Git installed for your user only rather than machine-wide. Check the other location and log whichever one is real:

    Test-Path "$env:LOCALAPPDATA\Programs\Git\bin\bash.exe"

4 · Node.js and Python

  1. Node runs JavaScript outside a browser. Several tools here are distributed through it, and n8n is built on it.

    winget install --id OpenJS.NodeJS.LTS -e --source winget --accept-source-agreements --accept-package-agreements

    Approve the elevation prompt. The .LTS on the end is not optional. The package named plain OpenJS.NodeJS installs the newest experimental release, which is too new for n8n — it will refuse to start later, and the error won't mention this step.

    LTS means Long Term Support. Two tools this week have hard minimums (n8n needs Node 22.22 or newer, Pi needs 22.19 or newer) and the LTS release clears both while staying inside what n8n supports.

    Without winget, download the LTS Windows Installer from nodejs.org/en/download. Click the LTS option, not Current.

  2. You'll use Python mainly to serve the course site locally, and agents reach for it when a task suits a quick script.

    winget install Python.Python.3.14 --accept-source-agreements --accept-package-agreements

  3. Same reason as before. Both installers changed PATH and this window can't see it.

  4. node -v
npm -v
python --version

    All three should answer with version numbers. Node must read 22.22 or higher, and below 25. If it's outside that, fix it now rather than discovering it on Thursday:

    winget uninstall -e --id OpenJS.NodeJS
winget install -e --id OpenJS.NodeJS.LTS

    If npm fails with "npm.ps1 cannot be loaded because running scripts is disabled", go back to step 11. That error is the execution policy, not a broken Node install.

  5. Windows ships a placeholder python.exe that opens the Microsoft Store instead of running Python. It hijacks the command and produces confusing failures rather than a clear message.

    (Get-Command python).Source

    You want a real install path — something under ...\Programs\Python\.... If the path contains \WindowsApps\, or typing python opened the Store, switch the placeholder off: Settings → Apps → Advanced app settings → App execution aliases, then turn off the entries named python.exe and python3.exe. Reopen the terminal and check again.

5 · Your three API keys

  1. Open Your API keys and read it once through. It covers what a key is, what each one drives, and what to do if one leaks.

    Everything below depends on these three variables being set correctly, so the five minutes pays for itself.

  2. Run these four lines. The first prompts you to paste the key rather than putting it in the command, which keeps the secret out of your shell history:

    $key = Read-Host 'Paste OPENAI_API_KEY'
[Environment]::SetEnvironmentVariable('OPENAI_API_KEY', $key, 'User')
$env:OPENAI_API_KEY = $key
$key = $null

    Line two saves it permanently for your Windows account. Line three also sets it in this window, so you can keep working without reopening anything.

  3. $key = Read-Host 'Paste XAI_API_KEY'
[Environment]::SetEnvironmentVariable('XAI_API_KEY', $key, 'User')
$env:XAI_API_KEY = $key
$key = $null

    This one drives OpenCode. Check it starts with xai- before you paste — mixing up two keys produces an authentication error that never tells you which key was wrong.

  4. $key = Read-Host 'Paste ANTHROPIC_API_KEY'
[Environment]::SetEnvironmentVariable('ANTHROPIC_API_KEY', $key, 'User')
$env:ANTHROPIC_API_KEY = $key
$key = $null

  5. A model id per provider should be posted in the pre-work channel. Set them once here and every later step picks them up — otherwise you'd be hand-editing four commands further down.

    If nothing has been posted yet, ask in the channel rather than saving a placeholder. If you use a current model id temporarily, replace it with the cohort pin before the write proofs. These are two variables you can change in ten seconds later, not a decision you're locked into.

    Change the two quoted values to the ids you're using, then run all four lines:

    $env:HB_OPENAI_MODEL = 'paste the OpenAI model id'
$env:HB_XAI_MODEL    = 'paste the xAI model id'
[Environment]::SetEnvironmentVariable('HB_OPENAI_MODEL', $env:HB_OPENAI_MODEL, 'User')
[Environment]::SetEnvironmentVariable('HB_XAI_MODEL',    $env:HB_XAI_MODEL,    'User')

    The first two lines set them for this window; the last two make them stick for every future one. These two values are the only thing in this guide you type rather than paste. The HB_ prefix keeps them from colliding with anything a tool reads on its own.

  6. Close the terminal, open a new one, and run:

    'OPENAI_API_KEY','XAI_API_KEY','ANTHROPIC_API_KEY' | ForEach-Object {
  '{0}: user={1} session={2}' -f $_,
    ([string][Environment]::GetEnvironmentVariable($_,'User')).Length,
    ([string](Get-Item "env:$_" -EA SilentlyContinue).Value).Length
}

    Three lines, each with two matching non-zero numbers. This prints only the length of each key, never the key, so it's safe to run on a shared screen.

    user=0 means it didn't save — re-run that key's step and check the variable name for typos. session=0 means this window is older than the variable; open another one.

    Model ids aren't secret, so check those by eye in the same window:

    'HB_OPENAI_MODEL','HB_XAI_MODEL' | ForEach-Object {
  '{0} = {1}' -f $_, [Environment]::GetEnvironmentVariable($_,'User')
}

    Both should read back the ids from the channel. If either still says paste the..., go back to step 27 — four later steps depend on these.

    If either id is unknown, leave that variable unset until staff posts a real id. Never save an empty value or the words paste the...; the tools will otherwise fail later with a blank model and the error will look like authentication trouble.

6 · Your smoke folder

  1. New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\Documents\HarnessBootcamp\prework-smoke"

    Each tool below writes one uniquely named file here. By the end you'll have four files side by side in Explorer, which is exactly what Monday's gate asks to see.

    A smoke test is the smallest check that proves a thing is genuinely alive. Here it means the agent authenticated, reached a real model, and put a real file on your disk. That last part is the part that counts.

  2. Every one of these tools will happily tell you it created a file it never created. Chat output is a claim; a file in Explorer is evidence.

    So for each tool: run the command, then open the folder and look. If the file isn't there, the tool did not pass, however confident its reply sounded. You'll use this same distinction on real work all week.

7 · Codex — your home for the week

  1. Codex isn't a separate download. It's a mode inside the ChatGPT desktop app, sitting alongside Chat and Work. When this course says the Codex app, that's what it means — and knowing that saves you hunting the Store for a product that doesn't exist.

    Use the web installer at get.microsoft.com/installer/download/9PLM9XGG6VKS, or install from PowerShell:

    winget install --id 9PLM9XGG6VKS -s msstore

    The package is Store-signed, so Store components may flash past while it installs. You don't need to browse the Store yourself, and you don't need a Microsoft account.

    If your laptop blocks Microsoft's distribution service entirely, there's a direct package — see When something breaks at the end. Unlike the rest of this stack, there's no second vendor to fall back on, so raise it early.

  2. Launch the app. You'll land on a signed-out screen whose main button offers to sign in with a ChatGPT account — which you don't have and won't use.

    Choose Sign in another way instead, paste your OpenAI key, and select Continue.

    This is the one tool in the stack that ignores OPENAI_API_KEY. Everywhere else the variable is what does the work; here it's the key you paste that counts. Setting the variable and expecting the app to find it is the single most common way to lose an evening on this step.

  3. Open the profile menu. It should report that you're authenticated with an API key.

    If it names a ChatGPT account instead, log out from that same menu and redo the previous step, taking the Sign in another way path.

  4. Now lock the door behind you, so a stray click can never bounce you to a ChatGPT login you can't complete:

    $cfg = "$env:USERPROFILE\.codex\config.toml"
New-Item -ItemType Directory -Force -Path (Split-Path $cfg) | Out-Null
$keep = @(if (Test-Path $cfg) { Get-Content $cfg | Where-Object { $_ -notmatch '^\s*forced_login_method\s*=' } })
Set-Content -Path $cfg -Value (@('forced_login_method = "api"') + $keep)

    That writes one setting into %USERPROFILE%\.codex\config.toml. Restart the app afterwards so it reads the change. From then on, an accidental account sign-in fails politely and points you back to the key.

    Four lines rather than one, because of how this file is shaped. A line like [windows] opens a table, and every plain setting below it belongs to that table. So a setting appended to the bottom of a file that already has a table header silently joins the table and stops working — nothing errors, the app just keeps asking you to sign in. These commands rewrite the setting at the top, above every table, which also makes them safe to run again any time you want to confirm the lock is still there.

  5. Choose Open project and pick the smoke folder you made in section 6: Documents\HarnessBootcamp\prework-smoke.

    The folder you open is the boundary. Codex reads and writes inside it and has to ask before reaching anywhere else on your machine.

    That's worth pausing on, because it's the shape of everything you'll do this week: you decide what the machine can see before you give it work, not after.

  6. Beneath the message box is a permissions control. Set it to Ask for approval.

    Don't skip this one. That setting is what switches the Windows sandbox on — the boundaries limiting which files Codex can change and whether it can reach the network. Left alone, you get a capable assistant with none of the guardrails the rest of the week assumes.

    The first time it runs, the app builds that sandbox and asks for an administrator prompt. Approve it: that's the stronger elevated sandbox, and it's the one you want.

    If your laptop refuses the elevation, or you see an error mentioning 1385, Codex can run with weaker but workable boundaries. Add this to the bottom of the same config.toml, in a text editor — it is file content rather than a command to paste into PowerShell:

    [windows]
sandbox = "unelevated"

    That is a table header, so it has to be the last thing in the file — everything below it belongs to the table, which is the trap step 34 describes. If you later re-run that step's four-line command, it rewrites the top of the file and leaves this table where it is.

    Log which of the two you ended up on. Knowing your own boundaries matters during the week, and it comes up directly on Tuesday.

  7. In the message box, ask for the file in plain language:

    Create a file named from-codex.txt in this folder containing exactly the text: codex works

    Approve the write when it asks — that prompt is the sandbox doing its job. Then open the folder in Explorer and look.

    You want the file on disk, containing codex works. A confident "I've created that for you" with nothing in the folder is a fail, and noticing the difference is the first operator habit this course builds.

    If it can't authenticate, the key is the problem rather than the sandbox — go back to step 32.

  8. Worth reading once now, so nothing surprises you mid-week.

    Your API key runs all of the app's local work, which is the whole course: projects, worktrees, code review, skills, scheduled tasks, the built-in browser, and the permission modes you just set.

    It does not unlock the cloud half of the product. Codex cloud, Sites, GitHub and Slack delegation, and voice all need a ChatGPT subscription, and you'll see them greyed out or absent. Nothing in this course needs them, so that's information rather than a problem — but if a tutorial online tells you to click something you can't find, this is usually why.

8 · OpenCode — your second engine

  1. On Tuesday you'll run the same frozen brief through the Codex app and through OpenCode, compare what comes back, and decide which you trust. That needs two genuinely different engines, so OpenCode runs on Grok via your xAI key while Codex runs on OpenAI.

    OpenCode is required, not optional. Without it, Tuesday has nothing to compare. You'll use it again on Wednesday to compare how a second harness expresses permissions.

  2. Check the pre-work channel for a pinned OpenCode build, and prefer that over whatever is newest.

    OpenCode ships fast and its Windows support sometimes regresses between releases — recent versions have had reports of the agent's file-writing tools failing on Windows specifically. A cohort is better off on one known build than on whatever shipped that morning.

    The pin names two things, a channel and a version, because winget and npm publish this tool on their own schedules and are usually a few releases apart. A version number on its own doesn't identify a build.

    If there's no pin, don't stall on it. Install from winget without the --version flag, then write down the channel and the exact version you landed on and post it in the channel — two people comparing notes is usually how a pin gets settled. You may end up switching builds later; that's a two-minute reinstall, not a redo of this section.

  3. If there is a pin, run only the line for the channel it names, substituting the version:

    # channel: winget
winget install --id SST.opencode --exact --version <pinned version> --accept-package-agreements --accept-source-agreements
    # channel: npm  — needs Node from section 4
npm install -g opencode-ai@<pinned version>

    If there's no pin, this is the whole command — the winget line without the version flag:

    winget install --id SST.opencode --exact --accept-package-agreements --accept-source-agreements

    Don't use the curl install command from OpenCode's website. That script is written for Mac and Linux shells and can't run on plain Windows PowerShell. There's no PowerShell version of it published, so the equivalent address just returns an error page.

  4. opencode --version

    If you installed against a pin, this should print that version exactly. If it prints anything else — higher or lower — an older install is probably still on PATH, or the other channel got used. Record both numbers in your log and mention it, rather than quietly upgrading to whatever is current. With no pin, whatever it prints is your answer; just write it down.

    Record the channel and the version in your log. Monday's gate asks for both, because knowing exactly which build you're on is what makes Tuesday's comparison mean anything.

  5. OpenCode picks up XAI_API_KEY from your environment on its own — there's no login step.

    opencode models xai --refresh

    You should get a list of Grok models in xai/… form. Note the pinned one — or the one you chose — in your log.

    An empty list means this window can't see the key. Open a new terminal and try again; if it's still empty, re-check step 28.

  6. When OpenCode finds Claude Code's files it reads them — ~/.claude/CLAUDE.md and any .claude/skills folder. If you install the optional Claude Code later in this guide, your second engine quietly starts working from the first one's notes, and two engines sharing one memory file will agree more than they should.

    Turn that off once as a user variable, so every window you open from now on inherits it:

    [Environment]::SetEnvironmentVariable("OPENCODE_DISABLE_CLAUDE_CODE", "1", "User")
$env:OPENCODE_DISABLE_CLAUDE_CODE = "1"

    Two lines because they do different jobs. The first makes the setting stick for every window you open from now on; it doesn't reach the window you're in. The second applies it here, so the write proof below and anything else you do in this window are covered too.

    New terminal, then check it took:

    $env:OPENCODE_DISABLE_CLAUDE_CODE

    You want 1 back. A blank line means it didn't stick — set it again and note it in your log.

  7. This uses the xAI model id you set in step 27:

    cd "$env:USERPROFILE\Documents\HarnessBootcamp\prework-smoke"
opencode run -m "xai/$env:HB_XAI_MODEL" "Create a file named from-opencode.txt in the current directory whose only contents are the text: opencode works"
Get-Content .\from-opencode.txt

    The file must exist in Explorer. If OpenCode reports success but the file isn't there, that's the Windows regression mentioned above — record the version and exact error, then post it rather than spending an hour on it alone.

9 · Pi — the minimal harness

  1. Pi is a minimal coding-agent harness you reshape to your workflow — not a sealed product with one opinion about how agents should work. Out of the box it is small on purpose: read, write, edit, and bash, plus a clean terminal UI. That is why this course starts you here — you can see the loop.

    What the marketing line “bare” often misses: Pi is built to grow. You can load skills on demand, install packages from npm or git, write TypeScript extensions (tools, commands, UI, lifecycle hooks), keep tree-shaped sessions you can branch with /tree, share runs with /export or /share, and run it four ways — interactive TUI, one-shot print/JSON, RPC, or embed via SDK. Fifteen-plus providers, model switch mid-session, prompt templates, compaction you can customize. If a feature is missing (plan mode, sub-agents, MCP, permission popups), the Pi answer is usually “build it or install a package,” not “wait for the vendor.”

    Out of the box it has no guardrails, and the detail people get wrong is worth reading twice. Pi runs with exactly your own permissions — no sandbox, no approval prompt, and no working-directory fence. Being "in" your smoke folder is a convention you are keeping, not a boundary Pi enforces: an absolute path or a ~ reaches anything your Windows account can reach, including your SSH keys and saved credentials. Shell commands also have no default timeout.

    Pi's own documentation says so plainly, and explains why: a partial in-process sandbox "would be easy to misunderstand as a security boundary while still depending on the host shell, filesystem, package managers, credentials, and extension code." Real isolation has to come from the operating system or a container. That is a sharper lesson about security theatre than most security training, and you will build on it during the week.

    For pre-work you only need install, one proof file, and shell reach. Give it small, specific tasks inside the smoke folder, read what it proposes, and don't leave it running unattended.

    Two more things to know now: /share uploads your whole session — including the system prompt and every tool result — to a public-by-URL gist, so don't use it on work material. And installing third-party Pi packages runs their code with full access to your machine, so don't install any this week that haven't been named for the course.

  2. powershell -c "irm https://pi.dev/install.ps1 | iex"

    This installer asks questions, so run it in a normal terminal window and stay with it. If it offers to install its own copy of Node, answer Y — that's it making sure it has a new enough version, and it won't disturb the Node you already installed.

    Wait for Pi was installed successfully.

  3. pi --version

  4. Pi can see all three of your keys, so you must name the model. Left to itself it picks one you didn't expect, and bills that provider:

    cd "$env:USERPROFILE\Documents\HarnessBootcamp\prework-smoke"
pi -p --model "openai/$env:HB_OPENAI_MODEL" "Create a file named from-pi.txt in the current directory containing exactly: pi works"
Get-Content .\from-pi.txt

    Use the pinned OpenAI model, or run pi --list-models to see what your keys can reach. The -p flag runs one instruction and exits instead of opening the interactive screen.

    There's no -m shorthand despite what several guides claim — it has to be --model.

  5. Pi needs Git Bash to run shell commands, and it only looks for it at the moment it first needs one. A missing shell therefore fails mid-exercise rather than at setup, so force the problem out now:

    pi -p --model "openai/$env:HB_OPENAI_MODEL" "Run the shell command 'echo bash-ok > bash-check.txt' and tell me the result"
Get-Content .\bash-check.txt

    If it reports no bash shell found, point Pi at the Git Bash path you recorded in step 17 by creating %USERPROFILE%\.pi\agent\settings.json containing:

    { "shellPath": "C:\\Program Files\\Git\\bin\\bash.exe" }

    The doubled backslashes are required — that file format treats a single backslash as an escape character.

10 · goose — recipe, tools, mode, schedule

  1. goose is a local-first agent platform (CLI required here; Desktop optional). It is more than a one-shot chat: you package a recipe (mission + parameters), choose a tool surface (extensions / MCP tools), set an autonomy dial (GOOSE_MODE, max turns), and optionally an unattended path (scheduler + retry).

    Thursday’s block uses those four levers as the tool-enforced half of an autonomy contract. Pre-work only proves install and one write — you are not learning the whole product tonight.

    Course default is the CLI. Desktop adds a recipe library and Scheduler UI; nothing in the Monday gate requires it.

  2. Read this before the next step. A winget package named goose exists and is a completely unrelated database tool that happens to share the name. It installs cleanly, reports success, and is the wrong program.

    The goose you want is from the Agentic AI Foundation (aaif-goose), and it has no winget package. Use the installer below. Docs: goose-docs.ai.

  3. Do this before installing. By default goose stores secrets in Windows Credential Manager, which fails often enough on managed laptops that its own documentation tells you to decline it. Setting this first means the installer never tries.

    [Environment]::SetEnvironmentVariable('GOOSE_DISABLE_KEYRING','1','User')
$env:GOOSE_DISABLE_KEYRING = '1'

    One quirk worth knowing: goose only checks whether this variable exists, not what it contains. Setting it to 0 or false also disables the keyring. To turn it back on you have to delete the variable entirely.

  4. goose reads your API keys from the environment, but it needs telling which provider to reach for. This reuses the OpenAI model id from step 27:

    if ([string]::IsNullOrWhiteSpace($env:HB_OPENAI_MODEL) -or $env:HB_OPENAI_MODEL -like 'paste *') {
  throw 'HB_OPENAI_MODEL is empty. Complete step 27 with a real model id, then open a new PowerShell window.'
}
[Environment]::SetEnvironmentVariable('GOOSE_PROVIDER','openai','User')
[Environment]::SetEnvironmentVariable('GOOSE_MODEL',$env:HB_OPENAI_MODEL,'User')
$env:GOOSE_PROVIDER = 'openai'
$env:GOOSE_MODEL = $env:HB_OPENAI_MODEL

    Setting these means you never have to walk goose's provider list, which is worth avoiding: it mixes API-key providers together with subscription ones like ChatGPT Codex, GitHub Copilot and Cursor Agent that need consumer logins you don't have. This course is API keys only — stay on the OpenAI pin, or whatever the channel names.

  5. Goose's Windows executable also needs the Microsoft Visual C++ 2015+ x64 runtime. The Goose download contains goose.exe only; it does not install the runtime, and Python's bundled DLLs are not a substitute. Install this first:

    winget install `
  --id "Microsoft.VCRedist.2015+.x64" `
  --exact `
  --source winget `
  --accept-source-agreements `
  --accept-package-agreements

    If winget cannot install it, download Microsoft's x64 installer directly from aka.ms/vs/17/release/vc_redist.x64.exe. Run it, choosing Install or Repair if it is already present. Do not download individual DLL files from an untrusted site.

    cd "$env:USERPROFILE\Downloads"
$env:CONFIGURE = "false"
Invoke-WebRequest -Uri "https://raw.githubusercontent.com/aaif-goose/goose/main/download_cli.ps1" -OutFile "download_cli.ps1"
.\download_cli.ps1

    The cd matters only because the installer downloads into whatever folder you are standing in, and the last section left you in the smoke folder. Keep that one for evidence files.

    If PowerShell refuses to run the script, use this form instead:

    powershell -ExecutionPolicy ByPass -File ".\download_cli.ps1"

    And if execution policy is locked by your IT department so neither form works, goose publishes a Git Bash path — you installed Git Bash back in step 15. Open Git Bash from the Start menu and run:

    curl -fsSL https://github.com/aaif-goose/goose/releases/download/stable/download_cli.sh | bash

    Note the address in all three. The project moved to aaif-goose, and older instructions pointing at block/goose will either fail or fetch a stale build. Current documentation lives at goose-docs.ai.

  6. The installer drops goose into %USERPROFILE%\.local\bin but doesn't add that folder to PATH — it only prints a warning that's easy to scroll past.

    $bin = "$env:USERPROFILE\.local\bin"
$userPath = [Environment]::GetEnvironmentVariable('PATH','User')
if (($userPath -split ';') -notcontains $bin) {
  [Environment]::SetEnvironmentVariable('PATH', "$userPath;$bin".Trim(';'), 'User')
}

    The if is there because this same folder comes up again in section 14. PATH is a list you append to, not a value you set, so without the guard running it twice leaves the folder listed twice. Note that this reads and writes your user PATH only; it never touches the system one.

    Then close and reopen the terminal.

  7. Get-Command goose -All
where.exe MSVCP140.dll
goose --version
goose info -v

    Get-Command goose -All should point at the aaif-goose executable, and where.exe MSVCP140.dll should print a Windows runtime path. If the DLL lookup prints nothing, the runtime install did not complete. goose --version must return a version before you continue.

    The second Goose command shows the provider, model, and environment variables it is actually using. Confirm they match what you set two steps ago.

  8. cd "$env:USERPROFILE\Documents\HarnessBootcamp\prework-smoke"
$env:GOOSE_MODE = "auto"
goose run --no-session -t "Create a file named from-goose.txt in the current directory containing exactly the line: goose works"
Get-Content .\from-goose.txt

    GOOSE_MODE is the autonomy dial. auto skips per-action approval so this smoke test can finish; on Thursday you will often set approve (or smart-approve) so the tool itself enforces a human gate — that is a real contract row, not just advice. --no-session keeps this proof from leaving a session file behind.

    Once the course repo is cloned, Thursday’s starter pack is mission_flesh/p6/ (watch_officer.yaml + goose_recipe_notes.md). You do not need to run that recipe tonight.

12 · n8n

  1. node -v

    n8n refuses to start on Node older than 22.22, and it isn't tested above 24. It exits immediately with a version message rather than failing subtly, which is at least honest. If you're outside that range, go back to step 18 before installing.

  2. npm install n8n -g

    This one is slow — often several minutes, with long silent stretches while antivirus scans each extracted file. That's normal. Let it finish rather than killing it, because a half-written global install is genuinely annoying to clean up.

    There's no n8n desktop app any more; running it from the command line is the current path.

  3. n8n start

    Leave that window open — it is the running server. Then browse to http://localhost:5678.

    If Windows Firewall prompts about Node, you can decline safely. Nothing here needs to reach beyond your own machine.

  4. n8n shows what looks like a signup screen asking for an email and password. It is not a subscription and not a login to anything. It creates a record in a database file on your own laptop, nothing is transmitted, and no verification email is sent. It also can't be skipped.

    Use any email address and a password of at least eight characters with a number and a capital letter. Write both down — you'll need them again on Thursday.

    Afterwards it offers to email you a free licence key that unlocks a few extra features. Skip it. The course uses none of them, and it's the only step that would contact n8n's servers at all.

  5. Press Ctrl+C in the window running n8n. The page at localhost:5678 stops answering, and your work stays saved on disk for next time.

    You don't need to build anything today — Thursday covers that, including pasting your OpenAI key into an n8n credential. Getting it to start and stop once is the whole task.

When something breaks

  1. Close every terminal and open a new one. That's the answer roughly nine times in ten, and it applies to every tool here.

    If a second new window doesn't fix it, the installer didn't update PATH. Find the program's folder — usually %USERPROFILE%\.local\bin — and add it:

    $bin = "$env:USERPROFILE\.local\bin"
$userPath = [Environment]::GetEnvironmentVariable('PATH','User')
if (($userPath -split ';') -notcontains $bin) {
  [Environment]::SetEnvironmentVariable('PATH', "$userPath;$bin".Trim(';'), 'User')
}

    If Get-Command goose finds the executable but goose --version exits with -1073741515 or 0xC0000135, this is not a PATH problem. Install the Microsoft Visual C++ 2015+ x64 runtime from step 55, close every PowerShell window, and run where.exe MSVCP140.dll before retrying. Do not reinstall goose or switch shells.

  2. Before assuming an install is broken, confirm the terminal:

    $PSVersionTable.PSVersion

    A version number means PowerShell, which is what every command here expects. An error means you're in Command Prompt or Git Bash, and the command was never going to work.

    See the table in step 9 for the prompt each one shows, and the three error messages that specifically mean "wrong window."

  3. That's the execution policy from step 11. Re-run it, then check Get-ExecutionPolicy -List.

    If MachinePolicy or UserPolicy shows anything but Undefined, IT controls this centrally and you can't override it — ticket them with the exact output. As a stopgap for npm specifically, the same commands work from cmd.exe, which ignores this policy: cmd /c npm install n8n -g.

  4. Work through these in order. Is the key set in this window (step 28)? Does it start with the right prefix for that provider? Is it the right key for that tool — XAI_API_KEY for OpenCode, OPENAI_API_KEY for the rest?

    The Codex app is the exception to all of that: it never reads the variable. It uses the key you pasted into Sign in another way. Check the profile menu — it should say API key, not an account. If it's wrong, log out there and redo step 32.

    If the Codex app keeps pushing you toward a ChatGPT login, confirm forced_login_method = "api" sits in %USERPROFILE%\.codex\config.toml above any [table] header — re-running step 34's four-line command puts it there safely — then restart the app.

    If a tool worked yesterday and fails today with a 429 or a quota message, the key has hit its spending cap. That's not something a reinstall fixes — post which key and what you were running.

    If goose info -v shows a blank provider or model, set a real model id in step 27, open a new window, and rerun step 54.

  5. Some managed laptops block the Microsoft Store and the msstore winget source outright. The ChatGPT desktop app ships only as a Store-signed package, so unlike everything else in this stack there's no second vendor to fall back on.

    The rescue is the package itself. Download ChatGPT-x64.msix and install it directly:

    Add-AppxPackage .\ChatGPT-x64.msix

    If that's blocked too, it's an IT ticket rather than something you can solve from your seat. Raise it the day you hit it — this is the one install with no workaround, and it's the one most likely to cost you Monday.

  6. Believe the folder, not the chat. Check you're where you think you are with Get-Location, and list it with Get-ChildItem.

    If the tool insists and the file genuinely isn't on disk, that's a real defect worth reporting — it has been a live issue on OpenCode for Windows. Record the tool, its version, and the exact wording, and post it.

  7. Stop and post in the pre-work channel with the step number, the exact error text, and what you've already tried. Move on to the next section while you wait — most of these are independent, so one blocked tool doesn't block the rest.

    A documented blocker you raised on Saturday is a small thing. The same blocker discovered Monday at nine is not.
