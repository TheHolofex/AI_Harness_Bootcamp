What an API key is

An API key is a long secret string that identifies you to an AI provider's servers. When a tool sends a request to OpenAI or xAI, it attaches the matching key, and that provider bills the request to the course account.

This is a different door from a consumer subscription. A key talks directly to a provider's metered platform. During setup, use the API-key path and do not sign into ChatGPT, SuperGrok, or another monthly plan.

The provider split matters just as much as the sign-in method. Keep the OpenAI key inside Codex. Use the xAI key for OpenCode, goose, the Pi lab, and the AI step in n8n. That keeps the expensive OpenAI lane narrow and makes the source of each charge easy to identify.

A key is a credential, not a setting Anyone holding your key can spend against it. Treat it the way you would treat a password: never paste one into a chat window, a shared document, a screenshot, a support ticket, or a project file. If a key does end up somewhere it shouldn't, revoking it takes about thirty seconds — the steps are at the bottom of this page, and using them is routine rather than embarrassing.

Put each key in the right place

The two keys take different paths. Paste the OpenAI key into Codex's API-key sign-in screen. Do not create OPENAI_API_KEY during setup; leaving it out prevents another harness from selecting OpenAI by accident.

Store the xAI key as a Windows user environment variable named XAI_API_KEY. A user variable belongs to your Windows account, survives a restart, and is available to each command-line harness you open.

Set the xAI key

Open PowerShell and run these four lines. The prompt keeps the key itself out of your shell history:

$key = Read-Host 'Paste XAI_API_KEY'
[Environment]::SetEnvironmentVariable('XAI_API_KEY', $key, 'User')
$env:XAI_API_KEY = $key
$key = $null

The first line collects the key without putting it in your shell history. The second saves it for your Windows account. The third makes it available in the window you are using now. The fourth clears the temporary variable.

Why not setx Most guides on the internet reach for setx NAME "value". It works, but it silently truncates anything past 1024 characters and it puts the key itself into your command history where the next person at your keyboard can scroll back to it. The Read-Host form above has neither problem, and it is the form the course uses throughout.

Check that xAI landed

Open a new PowerShell window — a fresh one, because a window that was already open when you set a variable never sees it — and run:

'XAI_API_KEY' | ForEach-Object {
  '{0}: user={1} session={2}' -f $_,
    ([string][Environment]::GetEnvironmentVariable($_,'User')).Length,
    ([string](Get-Item "env:$_" -EA SilentlyContinue).Value).Length
}

You want one line with two matching non-zero numbers. This prints only the length of the key, never the key itself, so it is safe to run on a shared screen.

If a line shows user=0, the key exists only in the window you typed it in and will vanish when you close it — run the set command again and check the variable name for typos. If it shows session=0, the value is saved correctly but this window predates it; open another new window.

The Codex app is the exception worth reading twice. It does not need OPENAI_API_KEY for this setup.

Instead, on the app's signed-out screen you choose Sign in another way, paste the key, and select Continue. It stores the key from then on. The large button beside that option offers to sign in with a ChatGPT account — that is the subscription path, and it is not the one you have.

You can confirm which path took hold from the profile menu, which reports either an API key or an account name. If it shows an account, log out there and sign in again the other way.

The install guide writes two top-level settings to %USERPROFILE%\.codex\config.toml: forced_login_method = "api" keeps Codex on key-based authentication, and model = "gpt-5.6-terra" keeps every new Codex task on Terra. If the model picker shows Sol or another default, change it back to Terra before you run the task.

What the key buys you there is all of the app's local work — projects, worktrees, code review, skills, scheduled tasks, its built-in browser. What it doesn't buy is the cloud half of the product: Codex cloud, Sites, GitHub and Slack delegation, and voice all require a ChatGPT subscription. Nothing this week needs them, but it explains why an online tutorial may point at a button you don't have.

Spending, and why your key might stop working

Every request spends against one of the two course accounts, and both keys have hard caps. Codex charges OpenAI. Every other required cloud harness charges xAI. The split makes a sudden spend increase easier to trace and limits how much can run through the OpenAI lane.

The signature is an HTTP 429 response, sometimes worded as insufficient quota or spend limit exceeded. If a tool that worked yesterday starts failing today and nothing else changed, check that before you start reinstalling anything. Post which key and roughly what you were running — raising a cap is a small change at the console end, so it's worth asking rather than assuming your install broke.

The habits that keep you well inside the cap are the same ones that make you a better operator, which is not a coincidence. Bound the work in your Direction Brief so the machine isn't looping on an unclear goal. Stop a run that has plainly lost the chat rather than watching it spend. Point at the folder that matters instead of the whole disk.

Keeping keys out of the course files

Never paste a key value into the course repository, an operator file, a module exercise, or a chat transcript you plan to share. Use the Windows environment variables and each tool's sign-in flow instead. Those keep the credential separate from the work the AI reads and edits.

Codex stores its OpenAI credential under %USERPROFILE%\.codex. The xAI key remains in your Windows user environment, outside every project folder. n8n stores the xAI credential you create later in its local data. None of those locations belongs in the course repository.

Revoking a key

If a key is exposed — pasted into the wrong window, saved into a project file, shared on a screen, or you simply aren't sure — report it straight away so it can be revoked. A revoked key stops working immediately and everywhere, and a replacement can be issued in its place. Say which key and roughly when — revoking and reissuing happens at the provider console, which is not somewhere you have access, so this is a message to send rather than a thing to attempt yourself.

For a replacement xAI key, repeat the four-line PowerShell step and open a new window. For a replacement OpenAI key, sign out of Codex and use Sign in another way again. Do not swap one provider's key into the other provider's lane.

Reporting a leak is the correct move, always A key that is quietly still exposed is a real problem. A key that was exposed and revoked within the hour is a non-event. Operators keep trails and raise things early — that is the same instinct this whole course is built around, applied to your own credentials.
