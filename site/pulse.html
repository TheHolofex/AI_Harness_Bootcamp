Close a work product

A closeout is not another lesson. It is the short release decision that follows the module’s real checks. Use the exact steps on the module page first; return here only when you need the pattern.

The five-minute closeout

1 · Open

Inspect the artifact

Open the file, workflow, score sheet, or configuration that will be used. A chat saying it exists is not the artifact.

2 · Check

Run the listed acceptance checks

Use the module’s observable checks. Record the result that changes the decision: a count, diff, source trail, score, held row, or run output.

3 · Decide

Release, fix, or hold

Fix a material finding before release. If it cannot be fixed now, hold the work and name the owner and next action.

4 · Record

Leave one useful note

Save the artifact path, decision, strongest evidence, residual risk and owner, and one rule you will reuse at work.

A release note worth keeping

Artifact: [path or workflow]
Decision: [RELEASE / FIX BEFORE RELEASE / HOLD]
Evidence: [the check and observed result]
Residual risk + owner: [risk — person or team — next action]
Reusable rule: [one sentence you will apply on the next real job]

The reusable rule is the lesson reflection. Write what will change on the next run, not a summary of what you did. No separate reflection chat or course score is required.

When a fresh reviewer helps

Use a clean reviewer only when a material judgment remains after the mechanical checks. Give it the complete artifact, the acceptance criterion, and the unresolved question. Ask for a neutral table: criterion · evidence observed · supported / partial / unsupported · severity · required fix. Review adds value only when its finding changes the artifact or the release decision.
