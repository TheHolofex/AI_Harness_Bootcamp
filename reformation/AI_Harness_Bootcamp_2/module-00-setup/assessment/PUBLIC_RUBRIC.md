# Module 0 public scoring rubric

This is the standard your work is measured against. The evaluator applies it to the supplied case with a protected acceptance control that is not on your machine — you cannot read it, edit it, or move what it decides.

A module result is `PASS` only when every gate below passes. Otherwise it is `HOLD`. Strong prose cannot compensate for an unsupported claim, missing authority, or an action that was not performed.

| Gate | Passing evidence | HOLD examples |
|---|---|---|
| Acceptance control | Confirmed before work began: a protected acceptance control applies, it cannot be read or edited from your machine, and the standard it applies is this rubric | Confirmation written after the draft; the practice checker treated as the deciding control |
| Delegation | Names work AI may do, judgment you keep, and one use AI must not perform | AI owns final acceptance or a real-world decision |
| Responsibility | Source rights, sensitive data, affected audience, sharing limit, real-world authority, and human decision-maker are answered before the run | Any item unresolved, or written after seeing the draft |
| Direction | Audience, outcome, sources, constraints, priority, acceptance, falsifier, prohibited result, stop, correction limit, and owner predate the run | Vague request, movable criteria, missing stop condition |
| Operation | Draft exists at the recorded path and the first checked result is produced within 60 minutes | Tool says it wrote a file but no file exists; unexplained time overrun |
| Source check | You compared a material claim with exact source text | Producer checks itself; citation does not support the wording |
| Falsifier | The stated falsifier was run against a deliberately wrong copy of the draft, and the observed failure is recorded verbatim | Falsifier stated but never run; a falsifier that fails nothing, with no record of what it therefore cannot catch |
| Capability and limit | Separates model output, product surface, harness control, and human decision, and names one capability and one limitation observed in this run | Generic claims about AI; a limitation read about rather than watched happen |
| Sharing decision | Draft is either passed for named class review or held; no public or real-world use is claimed | Publication, real audience, or decision authority implied |
| Correction | First failed check is preserved; no more than two correction attempts, then `HOLD` | Check weakened, original failure erased, manual patch called an AI result |
| Changed input | Prediction predates the run; the required statement changes; unrelated material facts stay unchanged | Post-result prediction, original overwritten, unexplained reader-facing change |
| Handoff | Another person can locate purpose, source, draft, checks, decision, limit, stop, and next inspection | Depends on live explanation or conversational memory |

## What the practice checker proves

The practice checker on your machine proves only that the named mechanical requirements are present. It cannot decide clarity, source interpretation, responsibility, or permission to share. Editing it changes nothing about your result: it is not the control that decides acceptance.

## Reassessment

A held outcome is reassessed on the same supplied case, against this same rubric, with the protected acceptance control applied again. Repair the work that was held; you will not be given a different case. The original result and the reassessment result are both preserved.
