# Module 9 facilitator runbook

## Session result

The learner transfers a runnable Last Count package for movement W-9. Technical evidence must show actual received-folder operation, disabled-control refusal, digest-validated restoration, and byte-identical reruns. The changed snapshot must retain destination custody while withdrawing unsupported usable quantity. A structural checker exit is not clean-session operation or human transfer.

**What the harness changes:** Without the bounded adapter, a closing officer can record a destination scan as usable effect. The supplied package processes all forty shipment lines and every closure, keeps custody distinct from release/confirmation, preserves the supported HOLD, and demonstrates stop and restore without author intervention.

## Before class

1. Check the published desk rules, practice task, forty-line snapshots, closure files, hostile paperwork, active control, frozen control and digest. The practice task is public, not a qualification secret.
2. Run the complete published lab in a new external work folder. Retain the first attempt, source/control hashes, every result and negative observation. Use `scripts/check_package.py` only for structure, dependencies and cross-case contamination.
3. Select any graded task using the same task schema under real evaluator custody outside learner/model work. Do not reuse the retired thin-case tasks or pretend a checked-in specimen is private.
4. Arrange an eligible recipient who did not take the core or observe construction. Retain the evaluator's original outcome ledger outside learner/model work. Without these prerequisites, qualification remains HOLD while technical practice continues.

## Recipient rubric

Use the six fields in the public rubric. Record first-attempt questions, exact commands, actual outcomes and any intervention.

| Field | Required observation |
|---|---|
| Purpose / bounds | Recipient identifies desk, exact task/time, audience, class-only scope and prohibited consequential use. |
| Operation | Commands work from the received package alone on the assigned task. No author path or chat history is needed. |
| Evidence interpretation | Recipient reconstructs custody/usable contributions, exclusions, shortfall, source revisions and closure dispositions. |
| Responsibility / limits | Recipient names the unresolved human decision and does not promote a structural or quantity-support pass into operational authority. |
| Stop / restore | Actual disabled run creates no new output and leaves the original unchanged; frozen-baseline validation succeeds; the restored run reproduces the original bytes, including a legitimate HOLD. |
| Next-owner handoff | A named next owner can locate inputs, controls, attempts, strongest evidence and unresolved decisions without coaching. |

Do not coach during the first attempt. If intervention occurs, record it and classify that attempt as guided practice. An agent-operated replay is engineering evidence only.

## HOLD conditions

Hold the affected lane when source/input integrity fails, a required dependency is absent, a result uses another case's authority, a stopped output appears, restoration is unsupported, or the package requires machinery outside its stated boundary. Preserve the first failure rather than rewriting results or deleting an attempt.

Hold qualification when the recipient, evaluator, independently held task, or original outcome ledger is missing or compromised. Technical restartability does not clear that hold. Retain historical run evidence as historical; it is not a substitute for the current recipient's observed performance.
